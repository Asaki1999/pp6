## 1. 一句话目标与成功标准

**一句话目标**：让「这个对象属不属于某个项目」变成 `1_业务对象` 上的一个开关（是/否），开关打开后自动长出与系统 `projectId` 逐字一致的「所属项目」链接字段，并把与项目对象同名/近名的字段**对齐成项目侧的定义（编码、物理列、类型、长度、选项候选值）**，相近名称必须经用户确认，且对齐后所有按字段编码引用的地方（表单控件/列表列/级联/隐藏规则/流程条件）同步改掉。

### 成功标准（可量化 / 可验收）

| # | 指标 | 目标值 | 验收方式 |
|---|---|---|---|
| S1 | 链接字段与系统范式的一致性 | 勾「是」后生成的 `<attribute>` 与 `project_create.projectId` 的 12 个键（`code/fieldName/name/dataTypeNew/datatype/objectType/length/isnull/isindex/options/sn 顺序/无 format`）**逐键相等**（`name` 允许用户改名，默认「所属项目」） | 断言 XML 字符串包含该 attribute；回归用例 `BO/PL*` |
| S2 | 精确同名字段的对齐率 | 项目对象 36 个业务字段中，除 §4 排除表里的，其余同名同族字段 **100% 自动对齐**（0 次手工） | 报告 `aligned` 条数 = 预期条数 |
| S3 | 相似字段零静默改写 | 相似字段默认**一条都不改**；未点「按勾选对齐」时出包产物与不含该特性时**逐字节相同** | 同一份 Excel 出两次包做 diff |
| S4 | 引用完整性 | 对齐后**0 处**残留旧编码：表单控件 `name`、列表 `columns/sort_field/parent_field/title_field/detail_field`、`2_字段.cascade_parent`、`8_隐藏规则.target/source`、`11_流程流转.condition_field` | 断言「旧编码在 workbook 里 0 命中」；回归用例 `FORM/LIST*` |
| S5 | 存量包不破坏铁律 | 存量包模式对齐后，原有字段 `fieldName` **0 处变化**、`sn` 0 处变化、除目标 `bo/*.xml` 外其余条目**逐字节相同** | `tools/check_patch.py` 现有断言全绿 + 新增对齐用例 |
| S6 | 全局字典不退档 | 反解→出包后 `dic` 字段仍是 `typeScope="GLOBAL"` + 原 `typeKey` + 原候选 key（不再出现 `对象_字段` 新 key） | 断言 XML 里 `typeScope="GLOBAL"` 存在且 key 集合不变 |
| S7 | 无快照不阻断 | 项目字段快照三档全不可用时，解析/出包/存量包全部照常成功，只多一条提示 | 回归用例覆盖「快照缺失」分支 |

| # | 角色 | 场景（As a … I want … so that …） | 关键诉求 |
|---|---|---|---|
| U1 | 实施顾问（合同 / 周报等**普通对象**，`流程驱动=否`） | 我要给「合同」「项目周报」这类普通对象勾一个「关联项目」，并让其中的「项目编号/项目状态/汇报类型」与项目对象**完全一致**，so that 合同与周报能按项目落库、按项目筛选、看板按项目汇总不会因为字段口径不同而串味 | 少填字段、编码/候选值不用手工抄 |

## 3. 功能需求池（P0 / P1 / P2）

> 术语：「**链接字段**」= 指向项目对象的 `object` 字段（`code=projectId`）；「**对齐**」= 把本对象某字段的定义键改成与项目对象同名字段一致；「**项目快照**」= 项目对象的字段清单（见 P0-0）。

## 4. 业务规则表（精确、可判定、可测试）

### B1 精确匹配 → 自动对齐（满足全部 5 条）

| 条件 | 判定 |
|---|---|
| 名称 | 归一化后**完全相同**：`N(x)=` 去首尾/中间空白、全角→半角、去掉中英文括号及其内容、去掉末尾「字段」二字。`N(项目状态)=N(项目状态)` ✔；`N(项目 状态)=N(项目状态)` ✔ |
| 类型家族 | 同族才自动（见 B8），跨族转 B2 弹窗 |
| 排除表 | 不在 B3 排除表内 |
| 编码占用 | 项目侧 `code` 在本对象内**未被其他字段占用**（`code` 或 `fieldName` 都不撞） |
| 语义角色 | 不是本对象的「自身主身份字段」（见 B3-4） |

### B2 相似匹配 → 弹窗确认（命中任一即相似；默认不对齐）

| 规则 | 定义 | 例子（→ 成立 / ✗ 不成立） |
|---|---|---|
| **S1 包含** | `N(我方)` 与 `N(项目侧)` 一方包含另一方，且**较短者长度 ≥ 2**，且长度差 ≤ 3 | 项目状态/状态 → 成立；汇报类型/项目汇报类型 → 成立；项目级别/级别 → 成立；项目名称/名称 → 成立但被 B3-4 拦下；备注/项目备注说明 → 长度差 4，✗ |
| **S2 编辑距离** | `N` 后编辑距离 ≤ 1 且较短者长度 ≥ 3 | 项目编号/项目编码 → 成立；项目阶段/项目阶段名称 → 成立（含 S1）；预算/预算金额 → ✗（长度差 2 但短者 2 字… 按 S1 成立） |
| **S3 编码/列名同源** | 编码相同或物理列名相同，但名称不同 | 我方「项目状态」自动生成 `stateId`（`state_id_`）↔ 项目 `stateId` → 成立；我方「项目编号」→ `xiangMuBianHao` ↔ 项目 `code` → ✗（不成立，正常） |

> 判定实现要求：纯函数 `similar(a, b) -> "S1"|"S2"|"S3"|None`，**可单测**，不调大模型（离线可用，符合 README「不配大模型也能用」）。

### B3 一律**不**自动对齐（绝不静默改写）

| # | 情形 | 处理 |
|---|---|---|
| B3-1 | **项目对象的 `name`（项目名称）** | 只提示、不自动对齐。理由：每个对象都有「本对象名称」语义，把合同的「项目名称」对齐成 `name`/`name_` 会把「项目名快照」和「本单据名称」混成一列；这一条**必须由人拍**（见 §8-Q2） |
| B3-2 | 系统字段（11 个 `id/tenantId/ip/deleted/createBy/createTime/updateBy/updateTime/version/baselineVersion/isDraft` + 流程 4 个 `processNode/processHandler/processDefId/processInstanceId`） | 一律跳过；`patch` 侧另有 `_RESERVED_CODES` 拦截（`patch.py:57-61`） |
| B3-3 | 我方字段本身已是指向 project 的 `object` 字段（即链接字段） | 视为「已满足」，跳过，不参与对齐（否则会把 `projectId` 对齐成项目的 `ppParentId` 之类） |
| B3-4 | 对齐会**改掉本对象自身主身份字段**（对象已有 `name`/`code` 且该字段是列表 `title_field` 或表单主标题） | 跳过并报告 |
| B3-5 | 对齐会导致**编码冲突**（B6）或**物理列名冲突**（B7） | 跳过并报告，需人工处理 |

### B4 链接字段已存在怎么办

| 情形 | 处理 |
|---|---|
| 已有 `object` 字段且 `objectType=project`（任意 code，如用户自己建的 `projId`） | **复用**，不再新增；报告 `= 复用已有链接字段 项目（projectId / 隶属项目）`；若其定义与 F3 不一致（长度不是 64、`isMultiple=true` 等）→ 只提示差异，不自动改（存量包模式下也不改 `fieldName`） |
| 已有字段 `fieldName=project_id_` 但 `objectType≠project` | **冲突**：报错并中止出包（`物理列 project_id_ 已被字段 X 占用且未关联项目，请先改字段名或改用现有字段`） |
| 已有 `dic` 字段叫「项目」但类型是选项 | 不视为链接字段；正常新增链接字段并在报告里提示重名风险 |
| 已勾「关联项目=是」但对象是本包内新建的 `project` 对象自己 | **拒绝**：自关联不允许（对齐 `relations.py` 自关联红线）；`validate` 报错 |
| 一个对象的多个字段命中同一个项目字段（B5） | 不允许，见 B5 |

### B5 多个字段命中同一项目字段

- 若两个本对象字段 `N` 后都等于项目同一个字段（如「项目状态」与「项目 状态」）→ **只对齐第一个**（按 `2_字段.sn` 升序），第二个标 `跳过：与字段 X 命中同一项目字段 project.stateId`，并在弹窗/报告里明确列出，让用户改名或删掉重复字段。
- 若相似（B2）命中同一项目字段多个候选 → 弹窗里按项目侧 `sn` 排序全部列出，**可多选但同一项目字段只能被一个本对象字段认领**（前端禁选，后端二次校验）。

### B6 编码冲突

| 情形 | 处理 |
|---|---|
| 项目同名同族字段的 `code` 已被本对象**另一个不同名字段**占用 | 不对齐，报告 `✗ 编码 stateId 已被字段「项目当前状态」占用`；不给自动改名（改名会牵连引用，风险 > 收益） |
| 项目字段 `code` 与本对象某字段撞名但 `fieldName` 不同 | 同上，跳过 |
| 对齐后本对象出现两个同 `code` | 出包前 `validate` 直接报错（现有校验已有该条），不允许产物出去 |

### B7 物理列名冲突（`fieldName`）

- **新建对象（同步包模式）**：`fieldName` 允许被对齐成项目侧的值（如 `name_`），但如果本对象另一个字段已占用该列名 → 跳过并报告（同 B6 口径）。
- **存量包模式（P0-5）**：`fieldName` **永不改**。项目侧与我方不同名时，保留我方列名，报告 `~ 保留物理列 project_state_（项目侧为 state_id_，存量包不改列名）`，并提示「若确需一致，属于线上 `ALTER`，须走 DBA 变更流程」。

### B8 类型家族（只能在同族内自动对齐）

| 家族 | 成员（`assets/fieldtypes.json` 的 `datatype`） | 说明 |
|---|---|---|
| varchar 族 | `varchar / user / department / attachment / i18n / dic / object / userGroupCate / autoNumber` | 物理列都是 `varchar`，互换不 `ALTER`（`README.md`「导入之后：线上还能改什么」实证 7 项可改） |
| number 族 | `number` | 改类型要 `ALTER` |
| datetime 族 | `datetime` | 同上 |
| date 族 | `date` | 同上 |
| clob 族 | `clob` | 同上 |

- 同族 → 自动对齐（B1）；**跨族 → 转 B2 弹窗**，并在弹窗里明确写 `⚠ 对齐会改变物理类型（varchar→number），建表期生效；存量包需 ALTER`，默认不勾。
- `isMultiple` 差异（我方多选 `true` / 项目单选 `false`）：跟项目走（项目侧为准），报告标注 `⚠ 多选→单选，长度 1000→64`。

### B9 选项字段来源冲突

| 我方 | 项目侧 | 处理 |
|---|---|---|
| 自定义字典（`BO_ATTR_DIC_TYPE`，自动生成的 `对象_字段` key） | 全局字典（`DIC_TYPE` + `report_type`） | **对齐为全局字典**（P0-3 要求），报告列出「候选值将被替换为项目侧 6 项」；若我方已有自定义候选值且包含项目侧没有的项 → 弹窗里额外警告「自定义候选值将丢失（3 项）」 |
| 全局字典 | 各不同 | 保留我方（不可判定），只提示 |
| 任一侧 `dic` 但项目侧无候选值（快照取不到字典块） | — | 不对齐，报告 `✗ 项目侧 report_type 无候选值快照` |

### B10 名称相同但语义不同（重点风险）

- 硬编码「语义可疑名单」：`项目名称 / 项目编号 / 项目简称 / 项目类型 / 项目级别 / 项目状态 / 项目经理`。
  这些在**非项目对象**上有两种可能：① 想存一份**快照文本**（如合同里记项目名），② 想**关联到项目主数据**（应通过链接字段 + 列表列实现）。
- 规则：名单内字段**即使名称完全一致也不自动对齐**，一律进弹窗，弹窗文案固定为：
  `「合同」中的「项目名称」与项目对象的 name（项目名称）同名。若只是记录项目名字，请选「不对齐」；若要与项目主数据保持一致，请选「对齐」（对齐后编码变为 name，物理列 name_）。`
- 名单外字段按 B1/B2 正常处理。名单是常量表，后续由产品维护（不写死在多处）。

### B11 存量包：已有字段只覆盖定义

| 差异项 | 存量包模式是否覆盖 | 依据 |
|---|---|---|
| `dataTypeNew / datatype / objectType / length / precision / format / isnull / isindex / defaultvalue / options / 选项候选值` | ✅ 覆盖（走 `patch` 的 `mode=replace`） | `patch.py` 覆盖规则：只改动过的键 |
| `code` | ❌ 不改（改编码会断表单引用；且线上元数据已有该 code） | `patch.py` 铁律 + P0-5 需求原话口径 |
| `fieldName` 物理列名 | ❌ 永不改 | `patch.py:458`「改名等于要求线上 ALTER」 |
| `sn` 行序号 | ❌ 不改（避免与已有 sn 撞号，`tools/check_patch.py` 已有断言） | `patch.py` 保真断言 |
| 新增字段 | ✅ 完全一致（含 `fieldName=project_id_`） | 新增不涉及 ALTER 既有列 |

### B12 无改动即报错（沿用现有语义）

- 用户勾了对齐但最终 `aligned=0, added=0`（全部被跳过）→ 出包前报错：`没有产生任何改动：项目对齐全部被跳过（原因见报告）`，**不允许**输出与原包相同的 zip 却写「已对齐 N 项」。

## 6. 边界与异常

| # | 边界 / 异常 | 期望行为 | 用户看到什么 |
|---|---|---|---|
| E1 | 项目字段快照三档全不可用 | 特性降级：可勾「关联项目」，但**只补链接字段**（用内置常量模板，不依赖快照），不做任何对齐；不阻断出包 | `项目字段快照不可用（未连库刷新、无随包快照、未上传项目包），本次只补链接字段、不做字段对齐` |
| E2 | 快照存在但项目对象字段数异常（<36） | 视为快照不完整 → 警告一次，按能对齐的对齐 | `⚠ 项目字段快照只解析到 N 个字段（预期 36+），对齐结果可能不完整` |
| E3 | Excel 未勾「关联项目」但字段名与项目一致 | **完全不动**（不得因为「同名」就自动改）；只在报告里给一条 P2 级提示 | `提示：字段「项目编号」与项目对象同名，如需一致请勾「关联项目」` |
| E4 | 勾了「关联项目」但 `2_字段` 为空 / 对象无字段 | 只补链接字段（1 个），正常出包 | 报告：`新增 1 / 对齐 0` |
| E5 | 字段是系统字段（用户误填 `id`/`createBy`） | 忽略该行（沿用现有「内置字段填了会被忽略」规则），不计入对齐，不报错 | 无额外提示（与现状一致） |
| E6 | 编码冲突（B6）/ 物理列名冲突（B7） | 跳过该项 + 警告，**不中止出包**（其余字段照常对齐） | `✗ 编码 stateId 已被字段「项目当前状态」占用，已跳过` |

| E8 | 存量包里已有字段与我方同名但 `fieldName` 为空 | 按「存量包不改列名」处理：保留包内实际列名（从 XML `fieldName` 读），只覆盖类型/选项 | 报告 `= 保留物理列（包内未声明，沿用导入时生成）` |
| E9 | 反解一份**全局字典**字段再出包 | P1-3 生效后保持 `GLOBAL`；P1-3 未上线前必须在报告里明确警告（不得静默降级） | `⚠ 字段 report_type 为全局字典，反解会退化为自定义字典（已知限制）` |
| E10 | 对齐后表单/列表未生成（Excel 只填了 `1_字段`/`2_字段`） | 对齐照常生效，报告 `表单/列表未填，无需同步引用` | 无额外提示 |
| E11 | `7_表单脚本` 里手写了字段编码 | 不自动改（无法解析），列「需人工核对」清单 | `需人工核对：表单 create_contract 的脚本引用了 项目状态（已改名为 stateId）` |
