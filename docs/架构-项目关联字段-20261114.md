### 0.1 按主理人修订执行（与 PRD 冲突处以本节为准）

| # | PRD 原文 | 本设计执行 |
|---|---|---|

### 0.2 与 PRD 的其余冲突（本设计已按修订处理，需主理人确认的列在 §9）

- **PRD 验收 A3 作废**：A3 要求「项目编号」自动对齐成 `code`。修订 R2 把「项目编号」列入语义可疑名单 → **默认弹窗、不自动对齐**。A3 的断言改为「弹窗出现一行，勾选后才对齐」。
- **PRD 验收 A2 的措辞调整**：A2 要求链接字段 `sn` 大于流程字段。本设计让链接字段**最后补**（在 `ensure_process_fields` / `ensure_system_fields` 之后），因此链接字段 `sn` 天然**大于所有已存在字段**（含流程字段、系统字段）。这与 A2 一致——注意实现顺序必须照 §4.2 的顺序，否则会反。
- **PRD §4-B10 弹窗文案**：去掉「项目类型/项目级别/项目状态」相关段落，只保留 4 项可疑名单文案。

### 1.2 关键决策与**否决理由**

| # | 决策 | 为什么 | 被否决的方案（及理由） |
|---|---|---|---|
| D1 | 对齐引擎独立成新模块 `pp6kit/projlink.py` | 与 `relations.py` 同构（analyze 纯只读 → parse_decisions → apply 服务端重校验），职责单一、可单测 | 塞进 `builder.py`：builder 已有 768 行、承担 6 件事，再加「跨对象字段池比对 + 引用重写」会没人敢动 |
| D2 | 对齐发生在**模型层、生成之前** | `gen_bo`/`gen_form`/`gen_tpl` 内的派生引用（`cascadeParentCode`、列表 `attrs`）自动跟随，只需改模型里的 code 字面量 | 出包后改 XML：要同时改 bo/form/data_template 三类 XML 且派生引用算不回来 |
| D3 | **链接字段在 `builder` 里补**（`ensure_project_links`），不在 `projlink.apply` 里补 | ① `sn` 必须排在系统字段/流程字段之后（PRD A2）；② `apply` 只做「对齐 + 改名 + 重写」，保持「analyze 不改模型 / apply 只改定义」的边界；③ 所有出包入口（web build / 单模块导入 / CLI / confirmed-excel 预览）共用同一个 builder 钩子，不会漏 | 在 `apply` 里补：`sn` 会落在系统字段之前（因为 builder 之后才补系统字段），且 `_cache_proj` 会被动改模型（F-F） |
| D4 | GLOBAL 字典用 `BoField.dict_ref/dict_name/dict_stru/dict_items` 四个字段承载，`options` **原样照抄** | 线上真实字段（`project.huiBaoLeiXing`）的 `options` 就是 `{"isMultiple":false,"isDefault":false}`，**没有** `optionSource` 键。合成 `optionSource` 会造出一个线上不存在的形态 | 复用 `object_type` 判断 GLOBAL：`object_type` 对 dic 已被 `dict_key()` 强占（F-C），分不清 |
| D5 | Excel 里持久化全局字典用「扩展参数」列的 **`dict_ref/dict_name/dict_stru/dict_items` 控制键**，`resolved()` 写出前剥掉 | 确认版 Excel 需要往返不丢（P1-1/P1-3）；控制键不在 `ATTR_ORDER` 里，剥掉后 XML 零污染 | 新开一列「字典类型」：`S_FIELD` 加列会牵动 `sheet_data` 位序 + 用户旧模板，风险 > 收益 |
| D6 | 决策头 `align` 的值只当**布尔许可**用，服务端重新算候选 | 前端可能拿旧 Excel 的 code 提交；信任前端等于允许静默改名（PRD S3「零静默改写」） | 前端传完整目标定义：一旦前端缓存过期就会把错定义写进包 |
| D7 | 改名**一律两阶段**（先 `__pl_tmp_N` 再终码） | 互换场景（A→B、B→A）单阶段会互相覆盖；统一走一条路径比按需分支更容易验证 | 只在检测到交换时才两阶段：两套路径，边界用例必踩 |
| D8 | 存量包侧**新增独立函数**（`_global_dict_lines` / `_rewrite_global_items`），不改 `_dict_lines` / `_rewrite_dict_items` | `tools/check_patch.py` 61 条保真断言全绿是硬门槛（PRD A14），改老函数等于动红线 | 给老函数加 `global_` 参数：61 条断言要重跑重审，收益不成正比 |
| D9 | 项目快照的**取数只放在 `tools/dump_project_fields.py`**，app 运行时只读 JSON | 安全红线：真实库只读、不联网。「刷快照」是运维动作，不该藏在 web 请求路径里 | web 里加「刷新快照」按钮直连库：把只读通道暴露到用户请求路径，出问题难界定责任 |
| D10 | `inspect` **不推断 `project_link`**（保持 False） | 反解→再出包会静默改包（多出链接字段 + 对齐），而用户只是想「拆了重造」 | 看到 `project_id_` 就推断：系统里 39 个对象有这个列名，误判面极大 |

### 2.1 模型层新增（`pp6kit/model.py`）

```python
@dataclass
class BoField:
    ...                                  # 既有字段不动
    # ---- 新增：全局字典引用（P1-3 + 项目对齐 R4）----
    dict_ref: str = ""                   # dictionaryType.typeKey（如 "report_type"），空=自定义(BO_ATTR)
    dict_name: str = ""                  # dictionaryType.name（"项目汇报类型"）
    dict_stru: str = ""                  # dictionaryType.struType（GLOBAL 实测 "1"）
    dict_items: list[dict] = field(default_factory=list)
    #   [{"key":"MonthlyReportModules","name":"月报","sn":146}, ...]  ← 原样照抄，短码不可重算

    def value_source(self) -> str:
        """表单控件/详情表单取值来源的唯一真相（替代 3 处 f.dict_key() 复制）。
        dic    → dict_ref or dict_key()
        object → object_type
        其余   → ""
        """

    def excel_options(self) -> dict:
        """写回 Excel「扩展参数」列用：options + 四个控制键（resolved() 会剥掉）。"""
```

`resolved()` 的两处改动（**必须成对**，否则 GLOBAL 会被打回自定义）：

```python
opts = dict(self.options)
# ① 先剥控制键（D5）：控制键只活在模型/Excel，绝不进 XML
ctrl = {k: opts.pop(k, None) for k in ("dict_ref", "dict_name", "dict_stru", "dict_items")}
if ctrl["dict_ref"] and not self.dict_ref:
    self.dict_ref = str(ctrl["dict_ref"]); self.dict_name = str(ctrl["dict_name"] or "")
    self.dict_stru = str(ctrl["dict_stru"] or ""); self.dict_items = list(ctrl["dict_items"] or [])

if type_new == "dic":
    if self.dict_ref:                      # ② GLOBAL 分支：照抄项目侧，不合成 optionSource
        object_type = self.dict_ref
        opts.pop("optionSource", None)
    else:
        object_type = self.dict_key() or None
        opts.setdefault("optionSource", "BO_ATTR_DIC_TYPE")
```

### 2.3 `projlink` 内部结构

```python
@dataclass(frozen=True)
class DictItem:  key: str; name: str; sn: int
@dataclass(frozen=True)
class DictMeta:  ref: str; name: str; stru_type: str; scope: str; type_sn: int; items: tuple[DictItem, ...]
@dataclass(frozen=True)
class ProjectField:
    code: str; name: str; type_new: str; datatype: str; field_name: str
    object_type: str; length: int | None; precision: int | None
    is_null: bool; is_index: bool; default_value: str; format: str | None
    sn: int; options: dict; dict: DictMeta | None

@dataclass
class Snapshot:
    source: str            # target_db | package_snapshot | package_upload | unavailable
    generated_at: str
    project: dict
    fields: list[ProjectField]
    system_codes: set[str]
    warnings: list[str]
    def field(self, code) -> ProjectField | None
    def pool(self) -> list[ProjectField]        # 已按 sn 排序

@dataclass
class LinkPlan:            # 链接字段
    action: str            # "add" | "reuse" | "conflict" | "reject_self"
    code: str; field_name: str; name: str
    existing: dict | None  # reuse 时的原字段描述（code/fieldName/差异项）
    note: str

@dataclass
class AlignAction:         # 一条对齐（exact 或 similar）
    field_code: str        # 对齐前我方 code
    field_name: str        # 对齐前我方 name（给报告看）
    target: ProjectField
    rule: str              # "E0" | "S1" | "S2" | "S3" | "S4" | "B10"
    rank: int              # 0..4，小者优先
    family_ok: bool
    suspect: bool
    auto: bool             # True=自动对齐，False=需弹窗确认
    rename_code: str       # 对齐后 code（= target.code，update 模式时留原值）
    rename_field: str      # 对齐后 fieldName（update 模式时留原值）
    diff: list[dict]       # [{"key":"code","from":"projectState","to":"stateId"}, ...]
    warnings: list[str]    # 多选→单选、候选值丢失、跨族改物理类型 …

@dataclass
class ObjectPlan:
    object_code: str; object_name: str
    linked: bool
    update_mode: bool                    # bo.exist_id 非空 → 不改 code/fieldName
    link: LinkPlan | None
    exact: list[AlignAction]; similar: list[AlignAction]
    conflicts: list[dict]; skipped: list[dict]
```

### 2.5 决策头 schema（`X-Project-Link`）

```json
{
  "version": 1,
  "snapshot": "8e3f1c…（可选：临时上传项目 zip 的 token，20 位 hex）",
  "objects": {
    "contract": {
      "linked": true,                             // false = 该对象完全不动（可撤销 Excel 的「是」）
      "linkField": true,                          // false = 只对齐、不补「所属项目」
      "align": {                                  // key = **对齐前**的字段 code
        "projectState": true,                     // 用户明确同意对齐（含相似项）
        "projectCode": false                      // 用户明确不对齐（覆盖自动判定）
      }
    }
  }
}
```

校验规则（`parse_decisions`，非法 → `ValueError` → HTTP 400）：

| 情形 | 处理 |
|---|---|
| 空 / 缺省 | 返回 `None`（等于「完全按 Excel 与自动判定走」） |
| 非 JSON / 非 dict / `version != 1` | `ValueError("X-Project-Link 需要 {\"version\":1,\"objects\":{...}}")` |
| `objects` 不是 dict；某项不是 dict | `ValueError` |
| `align` 不是 dict，或值不是 bool | `ValueError` |
| `objects` 里的对象 code 不在本包 | `ValueError("决策里的对象 X 不在本包内")`（与 `relations` 同口径） |
| `align` 的 key 在本对象字段里不存在 | **不算错误**，记入 `report.warnings`（Excel 改过了，不能因此拒服务） |
| `snapshot` token 非 20 位 hex 或文件不存在 | `ValueError("项目快照标识无效，请重新上传项目 zip")` |

### 2.6 存量包 spec 扩展（`/api/patch/*` 的 JSON body，不是请求头）

```json
{
  "token": "…", "targets": ["bo/001-contract.xml"], "fields": [...],
  "mode": "replace", "scope": "full", "allCopies": false, "syncForm": false,
  "linkProject": ["bo/001-contract.xml"],
```

### 3.2 名称归一 `normalize(name) -> str`

| 步 | 规则 |
|---|---|
| 1 | 全角 → 半角（`U+FF01–FF5E` 减 `0xFEE0`；`U+3000` → 空格） |
| 2 | 去掉所有空白（含 `\t\n\r`） |
| 3 | 去掉中英文括号及其内容（`（）` `()` `【】` `[]`），最多去 2 层嵌套 |
| 4 | 长度 > 2 时去掉末尾「字段」 |
| 5 | 结果为空 → 返回原串（避免空串被当成同名） |

**否决**「去掉『的』」（把「项目的状态」视为「项目状态」）：会让「项目的名称」与「项目名称」混同，而这正是 B10 要防的场景。

### 3.3 类型家族 `family(type_new) -> str`

一次 `pp6kit.fieldtypes.specs()` 查表取 `datatype`，再映射成 5 族：

| 族 | 成员（`datatype`） |
|---|---|
| `varchar` | varchar / user / department / attachment / i18n / dic / object / userGroupCate / autoNumber / formula / file |
| `number` | number |
| `datetime` | datetime |
| `date` | date |
| `clob` | clob / table |

同族 → 可自动；跨族 → 一律进弹窗（带「会改物理类型，存量包需 ALTER」警告）。

### 3.4 相似判定 `similar(own, target) -> str | None`

返回值即规则码。**判定顺序固定**（返回第一个命中者），排在前面的视为更强的证据：

| 规则 | 谓词 | 例子（→ 命中 / ✗ 不命中） |
|---|---|---|
| `E0` 精确 | `normalize(own.name) == normalize(target.name)`（且非空） | 项目状态/项目状态 → E0；项目 状态/项目状态 → E0 |
| `S3` 结构同源 | `own.code == target.code` 或 `own.resolved_field_name() == target.field_name`（名称还不同才走到这） | 我方「项目状态」自动编码 `stateId` ↔ 项目 `stateId` → S3 |
| `S4` 同义词归一 | `synonym_canon(normalize(a)) == synonym_canon(normalize(b))` 且两者原串不等 | 项目类别/项目类型 → S4；项目等级/项目级别 → S4；项目编码/项目编号 → S4 |
| `S2` 编辑距离 | `levenshtein(normalize(a), normalize(b)) <= 1` 且 `min(len) >= 3` | 项目阶段名称/项目阶段 → 同时命中 S1，S2 先返回 |
| `S1` 包含 | 一方包含另一方，且 `min(len) >= 2`，且 `abs(len差) <= 3` | 项目状态/状态 → S1；备注/项目备注说明（差 4）→ ✗ |

`synonym_canon`：按 `SYNONYM_GROUPS` 顺序把词替换成组内首项（`类别/分类→类型`、`等级→级别`、`编码/代码→编号`、`状况→状态`）。

**否决**复用 `fieldcheck.near_level()`：实测对「项目类别/项目类型」「项目等级/项目级别」「所属项目类型/项目类型」「项目阶段名称/项目阶段」**全部返回 None**（阈值 0.80 + 子序列豁免，刻意保守防误报）。相似判定必须是领域规则，独立实现、独立单测（`PL04`）。

### 3.5 候选选择 `match(own, target) -> (rule, rank) | None`

`rank = {"E0": 0, "S3": 1, "S4": 2, "S2": 3, "S1": 4}`。

单字段决策流程（`_decide(bo, own, pool, taken)`）：

```
cands = [(rank, rule, target) for target in pool if (rule := match(own, target))]
if not cands:                     → skipped{kind:"no_match"}
best = min(cands, key=(rank, target.sn))
suspect = normalize(own.name) in SEMANTIC_SUSPECT          # B10（修订后的 4 项）
family_ok = family(own.type_new) == family(best.target.type_new)
# —— 一律不自动（B3）——
if own 是系统字段 / 流程字段                  → skipped{kind:"system"}
if own 是指向 project 的 object 字段          → skipped{kind:"self_link"}   # B3-3
if best.target.code in taken                  → conflicts{kind:"target_taken"}  # B5
if 目标 code 已被本对象另一个**不同名**字段占用 → conflicts{kind:"code_taken"}    # B6
if 目标 fieldName 已被其他字段占用（新建对象） → conflicts{kind:"fieldname_taken"} # B7
if update_mode（exist_id 非空）               → 允许对齐但 rename_code/rename_field 保持原值，
                                                并在 kept 里注明「保留编码与物理列（更新模式）」
auto = (rule == "E0") and family_ok and not suspect and 无冲突
       and not 会改掉本对象自身主身份字段        # B3-4：目标 code=="name" 且本对象已有
                                                # code=="name" 字段被任一列表 title_field 引用
       and 不猜规则（S1..S4 一律 auto=False）
```

**同一目标只认一个我方字段**（B5）：收集完所有 `(own, best)` 后按 `(rank, own.sn)` 升序分配，已被占用的 target → 后续 own 记 `conflicts{kind:"target_taken"}`。

### 3.9 应用 `apply(project, decisions=None, snap=None, mode="excel") -> dict`

`mode`：`"excel"`（同步包路径）| `"package"`（存量包路径，由 `analyze_package` → patch 使用，`apply` 本身不处理）。

```
report = {applied, objects:{}, aligned:[], kept:[], skipped:[], conflicts:[],
          linkFields:[], rewrites:{}, scriptFormKeys:[], notices:[], noop:True}
snap = snap or load_snapshot()
pool = snap.pool()
for bo in project.bos:
    d = (decisions or {}).get("objects", {}).get(bo.code, {})
    # ① 决策覆盖 Excel：Excel 的「是」与决策的 linked 取交集（决策缺省=沿用 Excel）
    if "linked" in d: bo.project_link = bool(d["linked"])
    if not bo.project_link: continue
    if bo.code == PROJECT_CODE: raise ValueError("对象 project 不能关联自己（自关联不允许）")
    plan = _plan_object(bo, pool, d, mode)
    # ② 三阶段写入（顺序不能换）
    _apply_definitions(bo, plan)          # 写 type/datatype/objectType/length/precision/
                                          # isnull/isindex/defaultvalue/options/choices/dict_*
    renames = _apply_renames(bo, plan)    # 两阶段改名（D7）
    _rewrite_refs(project, bo.code, renames)   # ③ 引用重写（见下表）
    report …
# ④ 汇总
report["noop"] = not (report["aligned"] or report["linkFields"] or report["rewrites"])
report["scriptFormKeys"] = [表单 key for 该 bo 有脚本]
return report
```

对齐写入的**字段级**规则：

| 键 | 写法 | 说明 |
|---|---|---|
| `type_new` / `datatype` | 直接覆盖目标的 | `datatype` 由 `resolved()` 从 `type_new` 推导，一般不显式写 |
| `object_type` | dic → `dict_ref`；object → 目标的 `object_type`；其余清空 | |
| `length` / `precision` | 覆盖（`None` 也覆盖） | 多选→单选时长度按项目侧（64），报告标 `⚠ 多选→单选，长度 1000→64` |
| `is_null` / `is_index` / `default_value` | 覆盖 | |
| `options` | **深拷贝目标的 options**（R4，禁止合成 `optionSource`） | |
| `choices` | 目标为 GLOBAL dic → `[i.name for i in dict.items]`；否则沿用原 `choices` | |
| `dict_ref/dict_name/dict_stru/dict_items` | 目标 `dict` 非空时整体照抄；目标无 dict → 四个字段清空（回到自定义） | |
| `format` | 不单独存：由 `resolved()` 按 `type_new` 从 `fieldtypes.json` 推 | 12 维里的 `format` 归入类型维度 |
| `code` / `field_name` | **update_mode（`exist_id` 非空）→ 不变**；否则 = 目标的 `code` / `field_name` | 存量包永不改（§5 patch 条目） |
| `name` | 不变（用户的字段名有意义，报告里显示「项目编号 → code」足够） | 否决「跟着项目改名」：会让用户的 Excel 与产物对不上 |

**引用重写全量清单**（`_rewrite_refs(project, bo_code, mapping)`，缺一即不通过）：

| # | 落点 | 匹配集合 |
|---|---|---|
| 1 | `BoField.cascade_parent`（本对象所有字段） | `{old_code, snake(old_code)+"_"}` |
| 2 | `FormField.name`（`bo_code` 匹配的所有表单） | 同上 |
| 3 | `FormField.cascade_parent` | 同上 |
| 4 | `FormField.value_source`（仅当值等于旧 code） | 同上 |
| 5 | `ListDef.columns` | 同上 |
| 6 | `ListDef.sort_field / parent_field / title_field / board_group / gantt_start / gantt_end / gantt_progress / detail_field` | 同上 |
| 7 | `HideRule.target / source` | 同上 |
| 8 | `WfEdge.condition_field`（`wf.bo_code == bo_code` 的流程） | 同上 |
| 9 | `Bo.parent_field` | 同上 |
| 10 | `7_表单脚本`（`proj.form_scripts`） | **只检测不修改**：`if old_code in script` → 记入 `scriptFormKeys` + 报告「需人工核对」 |

`mapping` 的合法性自检（写模型前）：改完后该 bo 内 `code` 唯一、`field_name` 唯一，否则 `ValueError`（早失败，不留半成品）。

### 3.11 存量包 `analyze_package(data, chosen, spec, snap=None) -> dict`

## 8. 风险与回滚

| # | 风险 | 触发条件 | 缓解（已写进设计） | 回滚动作 |
|---|---|---|---|---|
| 1 | **已导入对象被要求改列名** → DBA ALTER | 用户在有 `exist_id` 的对象上勾关联项目，且我方 `fieldName` 与项目侧不同 | `update_mode`（`exist_id` 非空）一律不改 `code`/`fieldName`；存量包双保险（`_merge_attr_line` 永不改 `fieldName`）；报告写「保留物理列 X（项目侧 Y，存量包不改列名）」 | 决策头 `objects.<bo>.linked=false` 或 `align` 全 false；本特性对未勾对象零影响（PL12） |
| 2 | **字典重复导入**（GLOBAL typeKey 已存在 → 造出第二套字典） | 包里已有 `report_type` 字典 | `_dict_lines` 命中已有 typeKey 时只追加候选值、不重建类型；候选项按项目侧固定 key 复用（`_rewrite_global_items` 同名字复用 key） | 关掉该字段的 `align`；已产出的包可重出（patch 幂等：同 code 覆盖） |
| 3 | **表单脚本引用旧编码**（JS 无法静态解析） | `7_表单脚本` 里手写了被改名控件的编码 | 不自动改；报告列「需人工核对：表单 X 的脚本引用了 旧名（已改名为 新名）」；`scriptFormKeys` 进 view model | 若脚本必须改：用「确认版 Excel」比对脚本列后手工改，或收回该字段的 `align` |
| 4 | **性能**（51 × N 字段两两比对 + 多次重写） | 单包 20 个对象 × 50 字段 = 1000 次 `match`，每次 5 条规则 | 只对 `project_link=True` 的对象分析；`Snapshot` 按路径+mtime 缓存；`similar()` 先比长度差（`>3` 直接 S1 出局）再算编辑距离（带早停 `limit=2`）；实测目标 < 50ms/对象 | 若某包超时：notice 提示「对象过多，跳过相似分析，只做精确对齐」（`similar` 可用参数关闭，留 `analyze(..., rules=("E0","S3"))` 逃生口） |
| 5 | **离线快照过期**（`assets` 快照与线上库不一致 → 对齐到过时定义） | 用户机器无法连库，用的是随包快照 | 快照带 `generatedAt`，界面显示「字段快照来源：随包快照 2026-11-14」；`status="degraded"` 时 warning；`tools/dump_project_fields.py` 一条命令刷新 | 删掉 `~/.pp6kit/project_fields.json` 回到随包快照；或临时上传 `项目.zip`（第③档） |
| 6 | **两阶段改名泄漏临时码**（中途异常 → 字段 code 变成 `__pl_tmp_1`） | `apply` 里第二步抛异常 | 全部在**内存模型**上做，异常即整份放弃（不落盘、不出包）；`apply` 结束前自检「无 `__pl_tmp_` 前缀 + code/fieldName 唯一」，不通过则 `ValueError` | 刷新 Excel 重来；已产出的 zip 不受影响（文件名带日期，可回退上一份） |
| 7 | **「关闭即零变化」被破坏** | 新列/新提示让未勾选的对象产物变化 | reader 缺列容忍（默认 False）；`apply` 对未勾对象 `continue`；`ensure_project_links` 只处理 `project_link` 的对象；`_ensure_value_sources` 本身幂等 | 回归 `PL12`（byte-diff）红即是此项，优先修 |
| 8 | **GLOBAL 字典候选值取不到 → 导入后空下拉** | 快照只拿到 `typeKey`，没有 items | E7：仍写 `dictionaryType`（空字典）并提示「导入后需在字典管理补值」，不阻断出包（同 `gen_bo` 现有注释的处理） | 临时上传含字典块的项目包；或手工跳过该字段 |

## 9. 需要主理人拍板的事项（4 条，含我的建议）

| # | 事项 | 我的建议 | 影响面 |

| Q1 | **「项目编号」到底自不自动对齐？** PRD A3 要求自动（对齐成 `code`），主理人修订 R2 把它列入语义可疑名单（弹窗）。两者冲突 | **按 R2 走（弹窗）**。理由：合同里的「项目编号」多半是**手抄的项目编号快照文本**，对齐成 `code`（指向项目的关联字段？不，`code` 是 varchar 文本）语义上其实是「与项目主数据保持同一个编码格式」，风险低于「项目名称」，但与「项目经理」同属"可能只是快照"。若业务确认要自动，只需把 `projectCode` 从 `SEMANTIC_SUSPECT` 拿掉（一行常量） | PRD A3 验收、`PL05` 断言、S2 自动对齐率 |
