# PP6 Studio 回归用例清单

> 本文件由 `python tools/regress.py --report docs/测试用例清单.md` 生成，
> 内容直接来自 `tests/` 里的用例注册表——**不要手改**，改了会在下次生成时被覆盖。

共 172 条；核心链路 75 条。

## 什么时候跑

- 每次往 app 里迁功能（改 `pp6kit/`、`assets/`、`static/`）→ 全量跑一遍；
- 只改前端 → 至少跑 `-m webui -m security`；
- 新增功能 → 在对应 `tests/test_*.py` 里加用例（见文末「加用例的规矩」）。

```bash
./.venv/bin/python tools/regress.py            # 全量
./.venv/bin/python tools/regress.py --list     # 只看清单
./.venv/bin/python tools/regress.py -m patch   # 只跑改包
```

| `WEB07` | 核心 | 出包接口返回 zip 与文件名 | /api/build、X-Filename、content-type=application/zip |
| `WEB08` | 常规 | 出包响应带可解析的报告头 | X-Build-Report、counts/entries |
| `WEB09` | 核心 | 校验有错时出包返回 400 | 不返回半成品 zip、错误里说清哪一条 |
| `WEB10` | 核心 | 反解接口返回填写模板 | /api/inspect、返回 xlsx、X-Package-Summary |
| `WEB11` | 常规 | 反解坏包返回 400 且带摘要 | 不让前端卡在转圈 |
| `WEB12` | 核心 | 改包解析接口列出对象 | /api/patch/inspect |
| `WEB13` | 核心 | 改包预览接口返回变更明细 | /api/patch/dry-run、不产生 zip、用 token 复用已上传的包 |
| `WEB14` | 核心 | 改包出包接口能下载新 zip | /api/patch/build、返回 PK 开头、带 X-Filename |
| `WEB15` | 常规 | 空模板可下载 | /api/template、xlsx |
| `WEB16` | 常规 | 新增字段表模板可下载 | /api/patch/fields-template |
| `WEB17` | 常规 | 业务对象目录可查询 | /api/objects、返回列表、未接库时用随包快照 |
| `WEB18` | 常规 | 空请求体给出明确错误 | 不抛 500、提示没有收到文件 |
| `WEB19` | 边界 | 超过 30MB 的文件被拒绝 | 不把内存吃满、提示精简后再传 |
| `WEB20` | 常规 | 中文包名在响应头里正确编码 | X-Filename 需 URL 编码、否则浏览器存成乱码 |
| `WEB21` | 常规 | 改包接口拒绝伪造的缓存标识 | token 必须是 20 位 hex、防止拿路径读别人的文件 |

## security（12 条）

| 编号 | 级别 | 用例 | 验证点 |
|---|---|---|---|
| `SEC01` | 核心 | 非 zip 文件给出人话错误 | 不是抛一堆 traceback、用户知道要重新导出 |
| `SEC02` | 常规 | 空 zip 不崩，返回 0 个对象 | 提示改用别的工作区、而不是白屏 |
| `SEC03` | 常规 | 包内 ../ 条目不会写到目录外 | 产物里保留原条目名但不定向到磁盘、重点是别让程序崩 |
| `SEC04` | 核心 | 字段名里的 CDATA 结束符不破坏 XML | ]]> 必须被转义、否则 XML 直接坏掉 |
| `SEC05` | 核心 | 字段名里的尖括号与引号被转义 | <script> 不能原样进 XML |
| `SEC06` | 常规 | 超长对象名仍能出包 | 编码截到 40 字符、表名不超库限制 |
| `SEC07` | 常规 | 字段编码撞数据库关键字自动避开 | order/desc 这类、列名加尾下划线就不能再撞 |
| `SEC08` | 常规 | 200 个字段的对象能正常出包 | sn 连续、XML 不截断 |
| `SEC09` | 边界 | 名称里的 emoji 与全角符号不破坏包 | UTF-8 原文保留、XML 仍合法 |
| `SEC10` | 常规 | 重复的表单 key 被拦下 | 同名会互相覆盖、导入后只剩一张 |
| `SEC11` | 常规 | 改包时传空字段列表不产生空包 | 空改动应报错而不是给个原包副本 |
| `SEC12` | 边界 | zip 里混入非 XML 条目不影响出包 | 有些导出包带 .DS_Store / 说明.txt |

## 加用例的规矩

1. 在对应模块的 `tests/test_<模块>.py` 里写函数，用 `@case("前缀NN", ...)` 登记；
2. 编号在模块内递增，**已发布的编号不复用**（删了就留空号）；
3. 标题写「用户能感知的行为」，不写「测试某函数」；
4. `tags` 填这条用例真正守住的东西（如「物理列名不变」），回归失败时一眼看出影响面；
5. 断言要基于**真实产出**（解 zip、读 XML），不要只断言中间变量；
6. 加完跑 `./.venv/bin/python tools/regress.py -m <模块>`，再 `--report` 更新本文件。

### 新功能迁入时的最小动作

- 新增一个 HTTP 接口 → 在 `test_webui.py` 补一条「正常返回」+ 一条「坏输入 400」；
- 新增一种字段类型 → 在 `test_bo.py` 与 `test_form.py` 各补一条，断言 XML 里的真实属性；
- 改了生成逻辑 → 先跑全量确认无退化，再把新行为补成用例；
- 只能人工确认的（连库、大模型）→ 用 `skip("原因")`，并在验收单里注明手工步骤。
