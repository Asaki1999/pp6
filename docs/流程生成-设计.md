# 流程生成器（workflow）设计说明

目标：让「同一份 Excel 重新出包」能带上**可直接导入的流程定义 XML**，
而不是像现在这样回一句「流程请自己画」。

前置分析见 `docs/流程-分析.md`（XML 七段结构、四类节点、六条跨文件依赖）。

---

## 1. Excel 新增三张表

### 1.1 `9_流程`（流程头，一行一条）

| 列 | key | 说明 | 默认 |
|---|---|---|---|
| 流程名称 | `name` | 界面上的流程名，也是 XML 的 `<name>` | 必填 |
| 对象编码 | `bo_code` | → `businessType` | 必填 |
| 流程类型 | `workflow_type` | `normal` | normal |
| 流程分类ID | `category_id` | → `categoryId`（**不是对象的 typeId**） | 取 `0_项目设置 › 流程分类ID` |
| 标题格式 | `title_format` | 待办标题模板 | `${name}-${bo.name}-${bo.createBy}-${bo.createTime}` |
| 模块ID | `module_id` | → `moduleId` | 取对象/项目默认模块 |
| 启用 | `is_active` | 是/否 → `IsActive` | 是 |
| 已有流程ID | `exist_id` | 更新线上已有流程时填它原来的 id | 空=新建 UUID |
| 说明 | `desc` | 仅备注 | — |

### 1.2 `10_流程节点`（一行一个节点）

| 列 | key | 说明 |
|---|---|---|
| 流程名称 | `wf` | 关联 `9_流程` |
| 节点序号 | `id` | 留空按行序 1..N，非必须但便于流转表引用 |
| 节点名称 | `name` | 审批人角色名或「开始/通过/驳回」 |
| 节点类型 | `kind` | `开始 / 审批 / 判断 / 通过 / 驳回`（→ Start/Ongoing/Branch/Passed/Rejected） |
| 处理人类型 | `handler_type` | `角色 / 人员 / 无`（→ RoleSelection / UserSelection / None） |
| 处理人 | `handler_names` | 中文名，逗号分隔（只用于展示与核对） |
| 处理人ID | `handler_ids` | 组织角色/用户 id，逗号分隔，与上一列一一对应 |
| 办理时限(天) | `expect_days` | → `ExpectHandleDays`，审批节点默认 2 |
| 表单 | `form_key` | 留空自动：开始→对象的新建表单，其余→详情表单 |
| 业务状态 | `business_state` | `待发起/进行中/已完成/已失败`，留空按节点类型推导 |
| 退回节点 | `go_back` | 节点名或序号，逗号分隔；留空=自动取前面全部审批节点；填「无」=不允许退回 |
| 可选择下一处理人 | `pick_next` | 是/否 → `NextHandler` 走人工选择 |
| 允许转办 | `allow_handover` | 是/否 |
| 颜色 | `color` | → `ColorCode`，留空按节点类型给默认 |
| 备注 | `notes` | → `Notes` |

### 1.3 `11_流程流转`（一行一条出边，可整表留空）

| 列 | key | 说明 |
|---|---|---|
| 流程名称 | `wf` | 关联 `9_流程` |
| 起点节点 | `src` | 节点名或序号 |
| 终点节点 | `dst` | 节点名或序号 |
| 流转名称 | `name` | 按钮文案，留空自动（开始→提交，其余→同意） |
| 流转条件 | `condition` | `无条件 / 字段条件` |
| 条件字段 | `condition_field` | 对象字段编码或中文名 |
| 条件运算 | `condition_op` | 等于/不等于/大于/大于等于/小于/小于等于/属于/为空/不为空 |
| 条件值 | `condition_value` | 选项字段可直接写中文选项名，出包时换算成短码 |
| 条件值说明 | `value_label` | 仅显示用 |
| 顺序 | `order` | 判断节点的多条出边必填，1 起递增；留空按行序 |
| 通知 | `inform` | 是/否，判断节点默认否 |

> **`11_流程流转` 整表留空 = 按 `10_流程节点` 的行序自动串成一条直线**（跳过判断节点）。

## 2. 模型（`pp6kit/model.py` 追加）

```python
WF_START, WF_ONGOING, WF_BRANCH, WF_PASSED, WF_REJECTED = (
    "Start", "Ongoing", "Branch", "Passed", "Rejected")
WF_KIND_BY_LABEL = {"开始": WF_START, "审批": WF_ONGOING, "判断": WF_BRANCH,
                    "通过": WF_PASSED, "驳回": WF_REJECTED, "不通过": WF_REJECTED}
WF_STATE_CODES = {"待发起": "pending", "进行中": "running",
                  "已完成": "done", "已失败": "failed"}   # 映射到对象 processState 的选项名

@dataclass
class WfNode:
    wf: str; name: str; kind: str = WF_ONGOING; id: int = 0
    handler_type: str = "角色"; handler_names: list[str]; handler_ids: list[str]
    expect_days: int = 2; form_key: str = ""; business_state: str = "待发起"
    go_back: list[str]; pick_next: bool = False; allow_handover: bool = False
    color: str = ""; notes: str = ""

@dataclass
class WfEdge:
    wf: str; src: str; dst: str; name: str = ""
    condition_field: str = ""; condition_op: str = ""; condition_value: str = ""
    value_label: str = ""; order: int = 0; inform: bool | None = None

@dataclass
class Workflow:
    name: str; bo_code: str; workflow_type: str = "normal"
    category_id: str = ""; module_id: str = ""; title_format: str = ""
    is_active: bool = True; desc: str = ""; exist_id: str = ""
    nodes: list[WfNode]; edges: list[WfEdge]
```

`Project` 追加 `workflows: list[Workflow]`。

## 3. 生成器（新文件 `pp6kit/gen_workflow.py`）

对外只暴露一个函数：

```python
def render(wf: Workflow, bo: Bo, project: Project, snippets, wf_id: str) -> tuple[str, list[str]]:
    """返回 (XML 文本, 提示列表)。"""
```

### 3.1 输出骨架（逐字对齐样本，行序/属性序都照抄）

```xml
<workflowDefinition>
  <id>{wf_id}</id>
  <name>项目立项</name>
  <moduleId>{module}</moduleId>
  <categoryId>{category}</categoryId>
  <businessType>project_create</businessType>
  <workflowType>normal</workflowType>
  <titleFormat>${name}-${bo.name}-${bo.createBy}-${bo.createTime}</titleFormat>
  <designer>
    <FlowDefinition DefaultFlowChartVersion="1" Id="{wf_id}" IsActive="true" Name="项目立项"
                    ParallelGoBackMode="Self" SendBackHandlerMode="AllHandlers" SendBackMode="Allowed">
      <FlowCharts>
        <FlowChart IsPublished="true" Version="1"> …节点… </FlowChart>
      </FlowCharts>
      <Interceptors/>
    </FlowDefinition>
  </designer>
  <layout>[{"nodeDataArray":[…],"linkDataArray":[…],"version":1}]</layout>
  <nodePermissions>{"1":{…}}</nodePermissions>
</workflowDefinition>
```

**只出一版**（`Version="1"` + `DefaultFlowChartVersion="1"`）。样本里 30 版是编辑器历史，不是格式要求。

### 3.2 节点

```xml
<NormalActivity AllowHandover="false" ExpectHandleDays="2" Id="2" Name="研发项目管理主任" State="Ongoing">
```
- `Start` / `Passed` / `Rejected` 不带 `ExpectHandleDays`。
- `BranchActivity` 只有 `Id` / `Name`，**没有 `State`**。

### 3.3 流转

```xml
<Transition AllowAutoTransform="false" AutoTransformReferActivityIds="" CommentRequired="false"
            Id="{tid}" Inform="true" Name="同意" Order="0" Target="3" Type="Forward">
  <Condition>True</Condition>
  <Countersign>Any</Countersign>
  <NextHandler>ActivityHandler</NextHandler>
  <Properties>
    <IfHideComment>false</IfHideComment>
    <PreTransformEvents>[]</PreTransformEvents>
    <IfHideAttachment>false</IfHideAttachment>
    <IfHideCC>false</IfHideCC>
    <PostTransformEvents>[]</PostTransformEvents>
  </Properties>
</Transition>
```

条件流转的 `<Condition>` 是**双层 JSON**：

```python
cond = {"$type": "WorkflowConditionTreeTransitionCondition",
        "conditionJson": json.dumps(tree, ensure_ascii=False, separators=(",", ":"))}
# tree = {"condition":"AND","rules":[rule]}
```

`rule` 逐字对齐样本：

```python
{"rule_id": "0w89eil",           # 8 位随机小写字母数字即可
 "field": field_expr,            # 见下
 "label": 字段名,
 "type": "string" | "number",
 "input": "dictionary" | "number" | "linkdata",
 "field_data_type": "dic" | "number" | "object",
 "field_object_type": <字典key> oder None,
 "field_options": {...},
 "operator": "equal", "operator_label": "等于",
 "value": <短码或数值>, "value_label": <中文>,
 "boCode": bo.code, "format": ""}
```

`field_expr`：字段有 `objectType`（dic / object）时写 `(objectType)code`，否则写 `code`。

`field_options`：dic 用
`{"isMultiple":false,"isDefault":false,"uniqueCheck":false,"optionSource":"BO_ATTR_DIC_TYPE","columns":[],"identities":[],"format":null,"objectType":<字典key>,"dictionary":<字典key>}`；
number 用同一份但去掉 `objectType`/`dictionary`。

**条件值换算**：dic 字段的值必须写成选项短码，用 `gen_bo.dict_choice_codes(bo, field_code)` 把中文换过去；换不出来（用户直接填了短码）原样保留。

运算符映射：等于→`equal`，不等于→`not_equal`，大于→`greater`，大于等于→`greater_or_equal`，小于→`less`，小于等于→`less_or_equal`，属于→`in`（值写数组），为空→`is_empty`，不为空→`is_not_empty`。
`operator_label` 写中文原词。

### 3.4 节点属性（`Properties`）

按 State 出不同键集（样本实测，顺序照抄）：

| State | 键 |
|---|---|
| Start | `BeforeCompleteEvents=[]` `IfShowButtonOfConsult=false` `AfterEnterEvents=[]` `IfShowButtonOfSaveForm=true` `BusinessState=待发起码` `FormKey` `ColorCode=7` `BeforeEnterEvents=[]` `AfterCompleteEvents=[]` |
| Ongoing | `BeforeCompleteEvents=[]` `AfterEnterEvents=[]` `GoBackActivityIds=[…]` `BusinessState=进行中码` `Handler=…` `FormKey` `ColorCode=1` `BeforeEnterEvents=[]` `AfterCompleteEvents=[]` `GoBackConfig=…` `ReviewBusinessParams={"enabled":false,"reviewNodeTypes":[]}` |
| Branch | 只有 `ColorCode=2` |
| Passed | `BeforeCompleteEvents=[]` `AfterEnterEvents=[]` `IfShowButtonOfSaveForm=false` `BusinessState=已完成码` `FormKey` `ColorCode=3` `BeforeEnterEvents=[]` `AfterCompleteEvents=[]` `IfShowButtonOfAddReader=false` |
| Rejected | 同 Passed，但 `BusinessState=已失败码`、`ColorCode=8`、无 `IfShowButtonOfAddReader` |

`Handler` 字符串：

```
Chain:[{"header":{"label":"","texts":["科研管理负责人"],"ids":["1567950168366514176"],"type":"RoleSelection"},"nexts":[]}];SelectMode=Referenced;AllowSelectWhenNextHandlersEmpty=false;AllowSkipWhenNextHandlersEmpty=false;AllowMultiple=true
```

- `handler_ids` 与 `handler_names` 长度不一致时：缺名字用 id 顶上，缺 id 时报错（`validate` 拦）。
- 处理人类型=角色/人员但两者都空 → `None;SelectMode=Referenced;AllowSelectWhenNextHandlersEmpty=false;AllowMultiple=true`。

`GoBackActivityIds` = `"[1,2,3]"`（**紧凑 JSON，无空格**）；`GoBackConfig` = `{"name":"退回","commentRequired":{"1":true,"2":true}}`。

### 3.5 `layout`

- 分层：从 Start 出发按最长路径分层（同一层竖排）。
- `nodeDataArray[i] = {"activityId": id, "key": -(i+1), "text": 节点名, "category": State, "loc": "x y"}`（`BranchActivity` 的 category 用 `"Branch"`）。
- `linkDataArray[i] = {"key": -(i+1), "transitionId": tid, "text": 流转名, "points":[x1,y1,x2,y2], "from": 源节点key, "to": 目标节点key}`
- 间距：层间 220，行间 90，起点居中。

### 3.6 `nodePermissions`

```
{ "<activityId>": {"button":[], "field":[…], "column":[], "row":[], "opinion":[]}, … }
```

`field` 里逐项来自**节点使用的那张表单**的控件：

```python
{"field_options": <控件参数>, "hide": [{"type":"none"}],
 "code": bo.code, "read": [{"type":"all","subjectAssignments":[{"value":"allUsers"}]}],
 "edit": <见下>, "name": 控件name, "label": 控件label,
 "field_type": 控件类型, "required": [{"type":"none"}]}
```

- 第一项固定是 `{"name":"_p_title","label":"表单标题","field_type":"text","field_options":{},…}`
- `edit`：**开始节点** = `[{"type":"BpmRole","rightsId":"NodeTodoHandler,BpmCreator","rightsName":"节点待办人,流程发起人"}]`；**其余节点** = `[{"type":"none"}]`
- `field_options` 必须与表单控件一致 → 复用 `gen_form` 的内部函数：
  `parents = gen_form._cascade_parent_names(form)`；`ftype = gen_form._effective_type(ff, parents)`；
  `opts, _ = snippets.field_options(ftype)`；`fo = gen_form._apply_options(opts, ff, parents)`
- 容器（fieldset/card）不写进去（容器名是构建期随机短 id，写死反而对不上）

### 3.7 默认值推导（用户少填就靠这里）

| 项 | 推导规则 |
|---|---|
| `businessType` | `bo.code` |
| `moduleId` | `wf.module_id` → `bo.module_id` → `project.module_id` |
| `categoryId` | `wf.category_id` → `project.wf_category_id`（新设置项） |
| `BusinessState` | 节点类型 → 待发起/进行中/已完成/已失败，再换算成对象 `processState` 字典短码 |
| `FormKey` | 开始 → 该对象的新建表单 key；其余 → 详情表单 key；都没有就用第一个表单 |
| `GoBackActivityIds` | 留空 = 本节点之前所有 `Ongoing` 节点 |
| 流转 `Name` | 源节点是 Start → `提交`；否则 `同意` |
| 流转 `Inform` | 判断节点 `false`，其余 `true` |
| `Order` | 同一源节点内按行序 1..N（判断节点尤其重要） |

**`processState` 字段**：对象勾了「流程驱动」且存在流程时，自动补
`processState`（流程状态，dic，长度 64，选项 待发起/进行中/已完成/已失败），
短码用 `gen_bo._choice_code(name, sn, used, scope=dict_key)` 算，保证与流程里的 `BusinessState` 一致。

## 5. 校验规则（`validate.py` 新增 `_validate_workflows`）

| 级别 | 条件 |
|---|---|
| error | 流程名称为空 / 重名 |
| error | `bo_code` 在 `1_业务对象` 里不存在 |
| error | 没有 `开始` 节点，或开始节点多于 1 个 |
| error | 没有 `通过` 节点（流程跑不到终点） |
| error | 节点名称重复（同流程内） |
| error | 流转引用了不存在的节点 |
| error | 判断节点出边 < 2 |
| error | 审批节点既没处理人名字也没 id |
| error | 条件字段在对象里不存在 |
| warn | `categoryId` 为空（导入后流程会落到「未分类」） |
| warn | 判断节点出边 `Order` 有重复 |
| warn | 没有 `驳回` 节点（只能退回，不能终止） |
| warn | `business_state` 填了但对象没有 `processState` 字段（会自动补） |

用 `tests/_harness.py` 的 `build({...})` 造包，断言 XML 片段：

- WF01 最小三节点流程能出 XML，含 `<workflowDefinition>` / `<FlowChart` / `State="Start"`

- WF10 `layout` 能 `json.loads`，节点数与节点数一致
