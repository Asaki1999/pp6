## 一、致命问题：表单控件引用的字典全部错误（14/14）

**现象**：业务对象里选项正常一份，但表单上「固定值 + 候选值」那里候选值出现两遍。

**证据**：

```
bo 里的字典：  typeKey = xiang_mu_li_xiang_xin_xi_liXiangShenQingDanWei   ← 带对象前缀
控件引用的：   dictionary = liXiangShenQingDanWei                        ← 没前缀
```

**14 个 dictionary 控件，14 个全错**，正确的 0 个：

| 字段 | 控件引用的（错） |
|---|---|
| 立项申请单位 | `liXiangShenQingDanWei` |

> 这也极可能就是「业务对象不一致」报错的来源：控件绑定的字典在对象里不存在，
> 系统判定表单与对象不匹配。

## 二、严重问题：自动编号没有编号规则

`autoNumber` 字段的 `options` 是**空的**。

库里真实 autoNumber 字段必须有 `identities`：

```json
{"isMultiple":false, "isDefault":false, "uniqueCheck":false,
 "optionSource":"BO_ATTR_DIC_TYPE", "columns":[],
 "identities":[{"name":"自动编号","alias":"6881e46d",
                "regulation":"{yyyy}{MM}{dd}{NO}","noLength":5,
                "initValue":1,"step":1,
                "duplicateType":"allow","duplicateScope":"",
                "queryCondition":{"condition":"AND","rules":[]}}]}
```

缺了它，**导入后「项目编码」不会自动生成任何值**。

→ **已修**：`model.resolved()` 给 autoNumber 补默认规则（`{yyyy}{MM}{dd}{NO}`，流水 5 位）。

## 三、字段长度不合理（不致命，但不符合规范）

| 类型 | 我们的值 | 库里真实值 | 说明 |
|---|---|---|---|
| `dic` | **200** | 32 / 50 / 64 / 255 | 200 是 fieldtypes 默认值，被 Excel 覆盖了；选项存的是 8 位 hex，32 就够 |
| `user` | 200（申请人） | 64（创建人/更新人） | 同类型长度不一致 |
| `autoNumber` | 200 | 50 / 64 | 编号一般 50 足够 |
| `varchar` | 1（isDraft） | — | 系统字段，正常 |

**影响**：不影响导入，但字段偏宽会让界面显示和解码变慢，也不符合「长度按需调整」的手册要求。

**建议**：Excel 模板里 `dic` 不填长度时用 32，`autoNumber` 用 64。
