## 4. 已知问题 / Findings（2 项，均非阻断）

### F1 · 外层套目录的包被分类为 `extra_entries`，提示可能误导用户（主理人 item 6 指定复核）— 设计级 / 待拍板

- **文件 + 行号**：
  - 后端 `pp6kit/webui.py:1491`（`extra = any(e["kind"] not in white ...)`）、`:1492-1498`（`nested = any(... and e["kind"] not in white ...)`）、`:1500-1503`（`if extra: problem="extra_entries" / elif nested: "nested_dir"`）
  - 前端 `pp6kit/static/app.js:1503-1504`（`const extras = ...; if (extras.length) return extra_entries`）、`:1513-1523`（`nested` 过滤 + `if (nested.length)` 分支）
- **复现步骤**：构造 zip `外层目录/bo/001-x.xml` + `外层目录/form/002-y.xml` → POST `/api/inspect`。CDP 与 HTTP 双层实测：`X-Package-Summary.problem = extra_entries`，`classifyInspect().kind = extra_entries`。
- **实际**：卡片标题「包里有系统不认的多余条目（线上原话：**不支持的同步对象类型**）」，恢复动作「只保留 bo/ form/ data_template/ 三类裸 XML；**删掉 manifest / txt / 图标 / 说明文件 / __MACOSX**；不要往包里加任何新文件。」
- **期望（按 PRD §3 反解异常 / 场景 12 / 架构 §6.3 第 3 类）**：外层套目录应给出「**同步包文件缺少业务类型目录**」，恢复动作应是「解压后把 bo/ form/ data_template/ 直接放在 zip 最外层重新压缩」——即 `nested_dir` 分支已有的文案。
- **根因**：`nested` 与 `extras` 的判定条件都要求 `kind ∉ white`，`nested ⊆ extras`，而 `extra_entries` 优先级在前 → **`nested_dir` 分支数学上不可达（死代码）**，前后端一致。
- **误导性判断**：**是**。套层包里并没有 manifest/txt/图标，用户按提示去删这些文件无法解决问题；线上原话也给错了（应是「缺少业务类型目录」）。但**功能仍正确**：跳过误导性空 xlsx 下载、给出中文分类 + 恢复动作 + 实际条目名（`外层目录/bo/001-x.xml` 已列出，用户能看出多套了一层），因此不是阻断性缺陷。
- **建议**（遵守主理人「不要自行改优先级」）：
  1. **最小风险（推荐本轮）**：保留优先级，给 `extra_entries` 的 `title`/`recovery` 补一句套层判别，例如「若条目名形如 `xxx/bo/001-y.xml`，说明外层多套了一层目录 → 线上原话『同步包文件缺少业务类型目录』，请解压后把三类目录放最外层重新压缩」；
  2. 或（需改设计 §6.3 并经主理人批准）把 `nested_dir` 提到 `extra_entries` 之前、并把 `nested` 条件改为对 `kind ∈ white` 的条目判 `/bo//form//data_template/` 嵌套；
  3. 或接受现状并在交付报告/说明页静态注明。
- **路由**：不改码、不改优先级，报主理人裁决（本轮判定仍是 NoOne）。

### F2 · 极端 `summaryOnly` + `truncated` 组合出现「仅显示前 0 条」措辞 — 文案级 / 极低危

- **文件 + 行号**：`pp6kit/static/app.js:1711-1713`（`truncNote`）、`:1707-1709`（entryRows 的 summaryOnly 分支）、`:1796`（反解卡片）、`:1831`（交付报告）。
- **复现**：构造 `summaryOnly:true, entries:[], truncated:true, entriesTotal:120` 的 report 喂给 `renderPackageTable`。
- **实际**：显示 `<span class="chip warn">仅显示前 0 条，共 120 条</span>` + 「清单过大，仅显示统计摘要」+ 总数 120 + 4 数量列。
