### 边界与铁律（本 PRD 全程遵守）

1. **不重复 XML 层**：单层 zip + 裸 XML、顶层仅 `bo/ form/ data_template/`（数据菜单手建数据集另有 `dataset/`）、无 manifest/catalog/图标/权限文件、entry 命名 `^(bo\|form\|data_template)/\d{3}-[a-z0-9_]+\.xml$`、序号跨目录连续、撞名补 `__2`、comment `CONFIG_SYNC_NOTE:<发布说明>`、重复推送不去重、form 结构 100% 对齐、bo 仅内容性差异、字典 attrs 样式、dataset/ 形态结论 —— **均已闭环**。
2. 本次只落 **app 可见层五类**：数据结构（Excel 规格表列 / 内部模型 / 反解字段）、页面内容、列表字段、状态反馈、操作流程。
3. 保持 4 个工作区（导入包生成 / 已有包加字段 / 数据查询 / 设置）、桌面布局（固定深色侧栏 + 独立滚动工作区 + 底部状态栏）、现有 API（`/api/parse`、`/api/build`、`/api/import/<模块>`、`/api/inspect`、`/api/patch/inspect\|fields\|dry-run\|build\|workbook`）不破坏。
4. 只读约束：不对线上系统做任何写操作；资料均在本地，需线上复核的一律列「待确认问题」，不臆造。
5. **不以「变更区历史数据」作结论依据**；表单 / 列表与绑定对象成套分析；万物皆来源于业务对象；入口注意右上角三点（☰）/ 悬停菜单，不是普通按钮。
6. 若发现「已完成的 XML 层」之外的新缺口，必须给出确凿证据（本文 C5、C6 两条）。

### 产品定义（3 个正交目标）

- **G1 可见**：用户/QA 在 app 内即可看见同步包的目录分布、条目清单、数量列、comment 与导入路径，不必解压 zip 或读数据库。
- **G2 可辨**：zip 相关六类操作的正常 / 空 / 异常三态在界面上可区分、可恢复，异常文案对齐线上原话。
- **G3 一致**：规格表「说明」页、结果页、加字段工作区对「整包一把导入」与 `CONFIG_SYNC_NOTE:` 的口径一致，且**不改变任何出包字节**。

### User Stories

- As a 项目经理，我要在出包前看到「这个包里有什么、传到哪儿」，so that 不用解压也能确认产物与线上「发布工作区」同构。
- As a QA，我要在 app 内直接读到包内条目名、序号、comment 与重复副本，so that 能按差分法验收而不必写脚本。
- As a 实施人员，我要在反解 / 加字段失败时看到线上同款错误原因，so that 知道是包不合法还是内容为空，并知道下一步怎么做。
- As a 填表人，我要规格表「说明」页与实际能力一致，so that 不会因「一个 zip 只能属于一个模块」的旧文案而拆错包。
- As a 架构师，我要每条结论都映射到具体文件 / id / 函数名，so that 能低风险排期且不推倒重来。
