## 1. 控件分三档（运维说明的划分）

### 档 A · 直接支持的基础控件（拖进去就能用）

单行文本、多行文本、数字、日期、**隐藏域**、**富文本**、
人员选择、部门选择、**选择对象**、**关联对象信息（关联内容）**、
表格（表格字段）

### 档 B · 关联数据控件（要先配「关联数据 + 值来源」）

| 控件 | 配置 |
|---|---|
| 单选 / 多选 | 只支持：**选项、接口数据**；值来源 = 关联数据 |
| 下拉 / 多选框 | 关联数据 + 值来源 组合配置 |
| 对象 / 级联 | 对象 = 关联数据 + 值来源；级联 = 再加值来源**过滤条件** |

### 档 C · 未来支持 / 当前替代

| 想要 | 当前替代方案 |
|---|---|
| 表格（子对象） | 数据模板 + 子对象（缓存录入 → 自动化落库） |
| **计算属性** | 表单事件脚本：触发 → 计算 → 回写 |

> 口诀：**先建数据，再接控件；复杂交互交给事件脚本与自动化。**

## 3. 表单脚本 API（`java表单脚本方案.pdf`）

### 3.1 两类脚本

| 类型 | 对象 | 用途 |
|---|---|---|
| **表单脚本** | `form` | 表单的操作 |
| **模版脚本** | `template` | 数据模版会配置展示形式，template 是该展示形式的对象（多维表格、树、对话框） |

### 3.2 `this.$request` — 通用接口调用

如果 `this.$request` 不存在，用 `form.$aoborsoftUtils.request()` / `template.$aoborsoftUtils.request()`。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| url | String | 是 | - | 相对或绝对路径。相对路径例：`business/v3/rule/engine/exec`，其中 `business` 是后端微服务名 |
| method | String | 否 | `'get'` | get/post/put/delete/patch |
| params | Object | 否 | - | 追加到 URL 查询串 |
| data | Object | 否 | `{}` | 请求体 |
| isLoading | Boolean | 否 | false | 全屏加载遮罩，响应后自动关 |

```javascript
this.$request({
  url: '',
  method: 'post',
  isLoading: true,
  data: {}
})
```

### 3.3 脚本里手动调自动化

```javascript
this.$request({
  url: "business/v3/rule/engine/exec",
  data: {
    id: "自动化的ID",
    // 列表场景用 encodeURIComponent(JSON.stringify(params))
    inputParams: JSON.stringify({ /* 入参 */ }),
  },
  method: "POST",
}).then((res) => {
  if (res.state === 200) form.$message.success("执行成功");
});
```

### 3.4 事件：`$emit` / `$on`

表单脚本的 `form`、模版脚本的 `template` 都能触发/监听自定义事件。

### 3.5 常用工具

```javascript
// 根据人员 ID 取人员信息
this.$request({
  url: "platform/v3/employee/transfer",
  method: "post",
  data: { ids: ["人员ID"] },
})

// Loading
const loadingInstance = form.$aoborsoftUtils.getLoadingInstance(form)
loadingInstance.close()
```

### 3.6 `this.$dialog` — 弹窗里嵌表单

```javascript
this.$dialog({
  data() {
    return {
      formKey: "create_project_2",   // 表单 key
      pkValue: form.formParams.variables.id,
      readonly: false,
      showClose: true,
      buttonPriority: "inner",
      height: "40%",
    };
  },
  methods: {
    closeDialog() { this.$emit("close"); form.closeDialog(); },
    emitEventHandler(actionKey, args) {
      if (actionKey === "save") {
        const formData = form.getFormData();
        const jsonData = {
          boCode: this.$children[0].formDef.code,
          version: this.$children[0].formData.responses.version || 1,
          formKey: this.$children[0].formKey,
          pk: this.$children[0].formData.responses.id,
          data: JSON.stringify(formData),
        };
        // post 到 /business/v3/data/template/saveFormData/vo
      } else if (actionKey === "close") {
        this.closeDialog();
      }
      this.$emit("action-event", actionKey, args);
    },
  },
});
```

### 3.7 常用 REST 接口（手册直接给的）

```http
# 更新单个数据集的字段值
POST /iform/business/v3/data/dataset/updateFields
{ "key": "fqtqjb", "pkName": "id", "pkValue": "...", "data": "{\"字段编码\":值}" }

# 批量更新
POST /iform/business/v3/data/dataset/batchUpdateFields
{ "key": "fqtqjb", "pkName": "id_", "data": "[{...},{...}]" }

# 保存表单单个控件值
POST /iform/business/v3/form/saveFormFieldValue
{ "formKey": "...", "boId": "...", "boColumnName": "QingJiaTianShu", "value": "10" }
```

> 注意 `updateFields` 用 `pkName: "id"`，`batchUpdateFields` 用 `pkName: "id_"`，
> 手册原文如此、且强调 data 里每个对象的主键属性名要跟 `pkName` **完全一致**。

## 4. 表单生命周期钩子（脚本里用）

`Object.assign(JForm, { ... })`

| 钩子 | 时机 | 典型用途 |
|---|---|---|
| `onLoad(form)` | 表单加载 | 注入组件、回填数据、初始化子表 |
| `beforeSubmit(form, action, postValue, callback)` | 提交前 | 校验子表必填；`action` 取值 `saveAndContinue`/`save`/`submit`/`saveDraft` |
| `afterSubmit(form, action, postValue, callback)` | 提交后 | 调自动化落库；新主键在 `form.formParams.variables.id` |
| `beforeSubButton(tableForm, action, position, params, callback)` | 子表按钮前 | 放行/拦截 |

模版脚本（多维表格）的钩子：

| 钩子 | 用途 |
|---|---|
| `rowSaveBefore(template, args, callback)` | 行保存前，可写外键：`rowData.外键 = template.params.xxx` |
| `cellEditBefore(template, args, callback)` | 单元格编辑 |
| `beforeSubmit(template, action, position, selection, data, callback)` | 按钮提交前 |

常用的 `template.listDataAdd / listDataUpdate / listDataDelete` 三个数组
就是「缓存模式」的核心：新增/改/删先攒在这，统一由自动化落库。

## 5. 表格（子对象）的两种实现（运维说明详细讲了）

### 5.1 缓存模式（新建表单用）

```
明细表控件 → 新增数据模板
  · 外键过滤，外键列隐藏
  · 明细列开启编辑
  · 开启快速新增
  · onLoad 监控 listData 做汇总
  · 保存时触发回写自动化
```

链路：`表单 listData → 补齐外键 → 写入明细表`

### 5.2 实时编辑（详情表单用）

```
明细表控件 → libra 模板
  · 外键过滤，只取当前明细
  · 已落库数据实时读取
  · 按审批节点控制编辑性
  · 只读/闭屏按权限设置
  · 编辑后即时保存到子对象表
```

### 5.3 外键规则

**外键：计划明细 → 行动计划主键**（用于过滤当前流程，**不作为录入列**）

### 5.4 上线前检查

- 外键已隐藏
- 新增模板可快速新增
- 自动化 ID 正确
- 重新打开详情能看到明细
- 审批节点列权限符合预期

## 6. 表单初始化方式变了（运维说明重点标注）

> **从「额外触发」切换到「关联对象」**
> 旧做法：自动化 + 脚本初始化
> **新做法：关联对象信息实现**

但实际用例里脚本仍大量在用，典型两个场景：

**场景 A：新建表单带参初始化**

```javascript
onLoad: async function (form) {
  const projectId = form.params?.projectId;
  form.setData("projectId", projectId);
  if (!projectId) return;
  this.$request({
    url: "business/v3/rule/engine/exec",
    data: { id: "1440726417686925312", inputParams: JSON.stringify({ project_id: projectId }) },
    method: "POST",
  }).then((res) => {
    form.setData("projectManager", res.data[0].manager_ids);
    form.setData("orgId", res.data[0].org_id);
  });
}
```

**场景 B：流程审批通过后改其他对象**

「同意」线上的事件 → 自动化：触发器=流程线事件 → 更新数据（改项目状态为「进行中」）。

## 7. 流程要点（运维说明）

**主线**：业务对象承载数据 → 状态机/流程推进 → 人负责下一步。

- **每一种流程都有一个「流程对象」**，表单数据存在这个对象上
- 两种模式：
  - **传统业务对象模式**：业务对象 → 流程对象 → 提交/审批 → 状态流转
  - **简化状态机**：业务对象 + 表单 → 流程图做控件条件控制 → 状态变化找人
- 一次完整链路：**定义对象 → 配置表单 → 绘制流程图 → 加条件控制 → 指派处理人**
- **流程对象需冗余 4 个字段**，流转时反写
- 流程发起时向业务对象新增一条数据；节点没配表单则用全局表单
- **流程发起的表单要配在第一个节点上**
- 全局节点默认开启两项：**跳过第一个节点**、**相邻节点执行人相同则直接跳过**
- 流程的按钮在**流程图设计页面的节点上**配置，不在表单里
- 流程详情页右侧自带评论/日志卡片，无需另配

**立项流程（已有项目）的典型做法**：
1. 立项业务对象设**父对象为项目对象**（关联关系：`project_id_`，父子关系）
2. 把项目信息带进表单（下拉框值来源 = 项目值来源；部门/经理靠自动化赋值）
3. 流程通过后把项目状态改为「进行中」
