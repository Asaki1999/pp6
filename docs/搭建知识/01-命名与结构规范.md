# 01 · 命名与结构规范（硬性要求）

来源：`PP6/搭建规范手册.pdf`（65 页，2026-10-29 通读）。
这份是**验收标准**——不符合的包即使能导入，也不算合格交付。生成器必须逐条对上。

---

## 1. 编码、字段名、物理表名

| 项 | 规范 | 生成器现状 |
|---|---|---|
| 业务对象**编码** | 全小写，单词间 `_` 分隔 | ✅ `naming.to_english` 已按拼音小写 |
| **物理表名** | 编码加 `PP_` 前缀，如 `PP_syjl` | ✅ `table_name_for(code)` |
| 字段**编码** | **驼峰**，如 `baDian` | ✅ `naming.to_english` |
| 字段**物理名** | 全小写、`_` 分隔、**以 `_` 结尾**，如 `ba_dian_` | ✅ `camel_to_snake(code) + "_"` |
| 表单 **key** | 全小写、`_` 分隔 | ✅ |
| 列表/数据模版 **key** | 全小写、`_` 分隔 | ✅ |

> **关键提醒**（手册原话）：编码字段需采用小写形式，单词之间用下划线分隔；
> 字段为物理表字段名，要求单词小写、以 `_` 分隔、**且以 `_` 结尾**。
> 我们之前踩过的「objectType 要不要带尾下划线」正是这里的物理名规范，
> 但**自定义字典的 typeKey 不带下划线**——两者不是一回事，别混。

**命名可读性要求**：不得出现「项目类型ID」这类名字，应直接命名为「项目类型」。
→ 我们 `naming` 里那条「去 ID/表/表单尾缀」的规则正好对应。

## 2. 表单的四套标准（**这是最重要的部分**）

规范手册把表单分成 4 类，**每类的自定义 Class、标签宽度、弹窗方式、按钮位置都不同**。
我们之前只用一套 `extendAttr`，这就是「生成的表单不好看」的根因。

| 表单类型 | 套件模板 | 自定义 Class | 标签宽度 | 弹窗/尺寸 | 按钮位置 |
|---|---|---|---|---|---|
| **新建表单** | 新建表单页面 | **`pp-drawer-add`** | **106px** | 抽屉 / 紧凑 / 百分比-**45** | **右下角** |
| **详情表单（紧凑）** | 紧凑-详情 | **`pp-details-sideslip`** | **106px** | 抽屉 / 紧凑 / 百分比-**45** | **右上角** |
| **详情表单（展开）** | 普通-展开详情页-模板 | **`pp-drawer-details`** | **120px** | 抽屉 / 展开 / 百分比-**90** | 右上角 |
| **流程详情表单** | 流程-展示详情页-模板 | **`pp-drawer-details`** | **120px** | 抽屉 / 紧凑 / 百分比-**90** | 节点上配 |
| 其他（总览/设置页） | — | **`pp-setting-Overview`** | — | — | — |

**详情表单（紧凑）额外要求**：在表单属性处**开启单行编辑模式**。

**展开详情页顶部信息控件**：一般放 3 个，且**每个控件标签宽度单独设置**：

| 标签字数 | 宽度 |
|---|---|
| 2 字 | 56px |
| 3 字 | 70px |
| 4 字 | 86px |
| 5 字 | 100px |

### 2.1 按钮规范

- **按钮位置**：新建表单 = **右下角**；详情表单 = **右上角**
- **「取消」「保存」为标准配置**，「保存并继续」按业务需要
- **样式**：仅「保存」用「主要-蓝色」，其余用「次要-灰色」
- 普通按钮内边距：**图标+文字 = 12**；**仅图标 = 10**
- 普通按钮背景色与边框色均为 `#ffffff00`；按钮间无外边距，
  若右侧是「更多」按钮，则右边距 **8**
- 按钮数量超过阈值时出现「更多」按钮，超出的收纳进去

> 手册还指出：**多维表格默认「添加」按钮打开在线表单**，此时新建页面的
> 顶部工具按钮**从外部传入，表单内部配置的按钮将失效**。
> 「编辑页按钮」要在**表格视图设置最下方**配置。
> 并且【后续版本将不再支持从多维表格处传入表单按钮】。

## 3. 条件专用表单（我们的重要缺口）

**为什么存在**：业务对象是弱关联，自动化等场景里「关联数据、日期、人员」这些字段
只能退化成单行文本框，体验很差。所以专门维护一张「条件专用表单」，
预先把所有字段的**显示类型**配好，需要时直接加载。

### 3.1 内置字段的固定配置

| 字段 | 数据量大 | 数据量适中 + 无父子 | 数据量适中 + 有父子 |
|---|---|---|---|
| **ID** | **自定义对话框** | **下拉框** | **关联数据** |

| 字段 | 固定控件 |
|---|---|
| 创建时间 / 更新时间 | **日期控件** |
| 创建人 / 更新人 | **选择器-人员** |

### 3.2 命名规范

- 表单名：`条件专用_【业务对象名称】`，如 `条件专用_项目`、`条件专用_风险`
- 控件命名：不得出现「项目类型ID」，应为「项目类型」

## 4. 导入专用表单（按需）

- 表单名：`导入专用_【业务对象名称】`，如 `导入专用_项目`
- 支持的控件：单行文本、多行文本、数字、单选框、多选框、下拉框、日期控件、
  开关、选择器、关联数据、数据字典
- 会读取控件**标签文本**作为导入列名，读取**校验规则里的必填**（标红校验），
  读取**描述信息**作为备注
- **必填字段必须与新建表单保持一致**
- **禁止出现**：创建人、创建时间、更新人、更新时间、ID、版本、流程实例
- 列排序：常用字段靠前，**第一列一般为名称列**
- 备注要写清楚：
  - 关联客户 → 「请填写客户名称」
  - 销售人员 → 「请填写用户中文名或登录Id，当名称重复时则只能填写登录Id」
  - 预测成单概率（%）→ 「填写范围在1-100，且只能填写整数」
- 要设置「下载模版命名」，如「批量导入商机」「批量导入客户」

## 6. 常见坑（手册明写）

1. **字段少建了**：进业务对象录入后点「保存」，系统自动更新物理表。
   **不要点「发布新版本」**——搭建期没有历史数据，不需要版本。
2. **字段类型/字段名/物理表名要改**：走「表结构梳理」文档流程。
3. 业务对象保存后，**必须在操作列点「生成表」**，物理表才真正生成。
4. 单行编辑模式**只能处理已绑定对象属性的控件**；没绑定的要走
   自动化 / 批量编辑接口。
5. 业务对象多版本时，**条件专用表单的版本必须与业务对象当前主版本一致**。

## 7. 布局宽度：一行能放几个控件（实测推导）

这是个**必须按宽度算**的问题，不是审美偏好。手册规定抽屉宽 45%，
（2026-11-10 起生成器把面板宽度统一提到 90%，但一行两列的结论不变——
宽度变大只是让每格更宽松，不会让 3 列变得舒服。）所以列宽要先算账再看能不能塞。

**1920 屏、45% 抽屉 = 864px**，扣掉列间距和内边距后：

| 一行几个 | 每列宽 | 扣掉 labelWidth(106px) 后输入框 | 实际效果 |
|---|---|---|---|
| 2 | 432px | **约 310px** | 舒服，线上常态 |
| 3 | 288px | 约 166px | 「请选择」开始被截断 |
| 4 | 216px | 不到 80px | **塌成竖条**（用户反馈的截图） |

**结论：一行固定 2 个**（用户 2026-10-29 明确要求）。

不按表单宽度自适应的理由：
- 45% 抽屉下 2 列是唯一舒服的选择（每列 432px，输入框 310px）
- 3 列只剩 166px，「请选择」要截断
- 4 列不到 80px，直接塌成竖条
- 展开详情虽然是 90%，但一行 3 个仍比 2 个挤；
  统一成两列后**所有字段左右对齐成网格**，视觉上整齐得多

独占整行的类型不受限制：多行文本、附件、子表单、标签页、卡片。
`layout == 1` 时每个字段各占一行。

### 7.1 布局 V1.0：分区容器 + 表格布局V1.0（2026-11-10 定稿）

对照真实导出包（`PP6/表单/项目详情表单 1.zip` 详情页、`项目表单包含级联关系…zip` 立项表单），
系统的表单结构是**两层**，不是「一行一个容器」：

```
formDef
└── card / fieldset          分区，一个分区一个
    └── grid_layout          「表格布局V1.0」，一个分区一个
        └── 控件（parentId 指向 grid_layout）
```

- **`span` 只有两种取值**：`12`（半宽，两个并排）、`24`（整行）。
  一行里只放一个控件时必须给 `24`，否则右半边整片空白。
  **不要用 6**——四列会把输入框压成竖条（旧版生成器踩过）。
- `grid_layout.fieldOptions` **要写两份且必须一致**：
  - `columns`：扁平单元格清单 `{name:null, label:"单元格", fields:[控件id], span}`
  - `rows`：`{id, columns:[{id, span, colSpan:1, fields:[完整控件 JSON]}]}`
  - 控件本体（`formField`）的 `parentId` 指向 `grid_layout`；`rows` 里那份 JSON 的
    `parentId` 指向**单元格 id**；`columns[].fields[0]` 指向**控件元素 id**。三处对不上就空白。
- `rows` 里的控件 JSON 要带 `field_name`（物理列名）、`icon`、`modelKey`、`code`（对象编码），
  缺了设计器里图标变问号、或者字段绑不上列。
- 容器选型：**详情类用 `card`**（有标题栏、可挂工具栏），**新建/条件/导入用 `fieldset`**
  （更轻，抽屉里不挤）。

### 7.2 旧写法（`grid` 每行一个容器）已废弃

2026-11-10 之前生成的是「根 grid + 每行一个 grid + 每格 span=12」。系统能吃，
但和真实表单不是一套结构，设计器里打开也没有分区，46 个字段只能一条长龙。
现在只在**反解旧包**时兼容读取，新生成的包不再写这种结构。

### 7.3 占位符也要短

抽屉窄、输入框只有 300px，塞不下「请描述项目涉及的靶点或作用机制」这种长句。
占位符控制在 **10 字以内**；超长且截不出完整短语时，退回该类型的标准提示
（请输入 / 请选择 / 请选择日期），不要截成「请描述项目涉及的靶点或作…」这种半句。
