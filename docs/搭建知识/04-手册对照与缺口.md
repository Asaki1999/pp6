## C. 条件专用表单（缺口较大）

手册给出的存在理由：**业务对象是弱关联**，自动化等场景里「关联数据/日期/人员」
只能退化成单行文本框。所以要专门维护一张条件专用表单，预先配好所有字段的显示类型。

### C.1 内置字段的固定控件（⚠️ 未实现）

| 字段 | 数据量大 | 适中无父子 | 适中可检测父子 | 实现状态 |
|---|---|---|---|---|
| ID | 自定义对话框 | 下拉框 | 关联数据 | ❌ 未按此判断 |
| 创建时间 / 更新时间 | 日期控件 | | | ⚠️ 现在是 datetime 但没针对条件表单特化 |
| 创建人 / 更新人 | 选择器-人员 | | | ⚠️ 同上 |

### C.2 命名（❌ 未实现）

| 规则 | 现状 |
|---|---|
| 表单名 `条件专用_【对象名】` | ❌ 现在是 `fetch_basic_xxx` |
| 控件名不得出现「XX ID」 | ⚠️ 依赖 naming |

### C.3 导入专用表单命名（❌ 未实现）

- 表单名应为 `导入专用_【对象名】`（我们叫 `import_xxx`）
- 应设置「下载模版命名」，如「批量导入商机」

## D. 导入表单的硬性约束（❌ 全部未校验）

| 规则 | 状态 |
|---|---|
| 必填字段必须与**新建表单一致** | ❌ 没有交叉校验 |
| **禁止出现**创建人/创建时间/更新人/更新时间/ID/版本/流程实例 | ❌ 没有校验 |
| 第一列一般为名称列，常用字段靠前 | ❌ 没有排序策略 |
| 需给导入列写备注（选择器要写提示语） | ❌ 没有生成 |

**这几条都是能被机器检查的**，值得加进 `validate.py`：
生成导入表单时，若包含系统字段 → 直接报错；必填集合与新建表单不一致 → 报错。

## G. 流程相关（暂不做，但要知道边界）

- 流程对象需**冗余 4 个字段**供流转反写
- 流程发起的表单必须配在**第一个节点**上
- 流程按钮在**流程图节点**上配，不在表单里
- 全局节点默认开启「跳过第一个节点」「相邻执行人相同则跳过」
- 立项类：立项对象设**父对象为项目**（`project_id_` 父子关系），
  通过后自动化改项目状态

## H. 下一步优先级建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 列表工具栏「添加」按钮 + 级联在线表单 | 不做的话列表点不出新建表单，等于不可用 |
| **P0** | 条件专用表单的控件选型（ID→下拉/关联，时间→日期，人→选择器） | 手册明确要求，且是「弱关联」问题的正解 |
| **P1** | 导入表单约束校验（禁系统字段、必填与新建一致） | 能被机器检查，成本低收益高 |
| **P1** | 表单命名规范（`条件专用_xx` / `导入专用_xx`） | 一行代码的事，但影响可读性 |
| **P2** | 显示字段的对齐/宽度/固定列 | 影响「好不好看」 |
| **P2** | 按钮内边距 / 更多按钮 | 细节打磨 |
| **P3** | 数据集：按手册建独立数据集（类型=物理表） | 需要先拿到真实样例确认服务端是否接受 |
