#### 2.3.1 四种值来源形态（2026-11-20 补）

线上 333 条规则（266 份模板只读统计）里 `source` 与 `field_source` 是**两个维度**，
只有这 4 种组合真实存在；白名单外的写法工具直接报错，不降级也不猜：

| 值来源 | `source` / `field_source` | `id`/`field` | `operator` | `value` | 表单侧 `link_condition` |
|---|---|---|---|---|---|
| 表单控件 | `dynamic` / `formField` | 目标列物理名 | 任意 | **恒 `"text"`** | **写一条**（`mode=bind`，`value`=本表单控件编码） |
| 固定值 | `fixed` / `formField` | 目标列物理名 | 任意 | 字面值（数字列保持 JSON number；`in` 用 `"a,b"`；`is_null`/`is_not_null` 为 `null`） | 不写 |
| SQL 片段 | `fixed` / `sqlSnippet` | **整段 SQL**（`id==field==SQL`） | **`""`** | `null` | 不写 |
| 系统变量 | `systemVariable` / `formField` | 目标列物理名 | 任意 | 变量名（线上只见 `currentUserId`） | **不写**（待实测：线上仅 3 条且都在「命名条件组」里，拿不到普通值来源的表单侧样本） |

另外三条与形态无关的硬事实：

- `field_type` / `field_input` **恒 `"string"` / `"text"`**（线上 333/333，含
  `type=number`、`input=number` 的数字列）；决定算子集合的是 `type` / `input` ——
  它们才随列类型变（number 列 → `number` / `number`）。数字 / 日期列过滤的算子
  集合会不会因此退化**待实测**（需要一份「数字列 + 小于等于」的包导入核对）。
- 表单侧一个控件挂多条条件时，`fieldName` **恒为 `<rule_id>_1`**，不是索引
  （线上 `0xi0u6u_1 / 1jz6tyg_1 / 1vnhwwc_1` 三条全是 `_1`）。
- 多条规则落在**同一个** `filterConditions` 条件组里，组内 `filter.condition`
  取 `AND` / `OR`（线上 269 AND / 1 OR）；本期只生成 1 个组。
- `rule_id` 由 `stable_code(f"{值来源key}:{规则下标}:{目标列}")` 派生（7 位小写），
  同一份 Excel 两次出包不变；值来源侧与表单侧读**同一份归一化结果**，不各算一遍
  （各算一遍就会分叉，表现正是「表单上配好了、下拉里却是全量」）。
  下标进 seed 是为了「同一列挂两条规则」不撞号。

工具侧的配置入口（两种，等价）：

- Excel `6.1_值来源` 的「过滤规则」列（JSON，见 `pp6kit/spec.py` 的列说明）；
- app 里值来源面板的「过滤规则」行列表（字段 / 运算符 / 值来源 / 值）。

`过滤规则` **留空**（或老工作簿没有这列）= 老口径（按「过滤字段/过滤目标/自动」
+ 同名推导，产物与改动前逐字一致）；写 **`无`** = 一条过滤都不要；非空 = 完全
按规则、忽略上面两列（Excel 回写时那两列会留空，避免出现两套配置）。

## 四、详情表单里的关联字段（原生证据）

样本：`PP6/表单/项目详情表单 1.zip` → `form/001-project_summary.xml`。

详情/基本信息的 object 字段都是 **selectObject**，且**没有** `value_source`：

```json
{"boCode":"classification","store":"id","multiple":false,"display":true}
```

因此：**新建表单用 linkdata（带值来源+联动），详情表单用原本字段类型 selectObject**。

## 五、本次要落到生成器的能力

1. **object 字段 → 新建表单 linkdata**
   - 自动建/接值来源（`type=valueSource`），`unique/uniqueField` 默认 `id_`
   - 写 `linkdata`、`link_config`、`link_linkage`、`link_condition`、`init_linkage` 等键
2. **详情表单保持原类型**：object → `selectObject` + `boCode` + `store=id`（无 value_source）
3. **联动数据**：值来源返回列 → 本对象同名字段自动映射（如 专业 `zhuan_ye_` → `zhuanYe`）
4. **值来源过滤条件 / 返回结果可在 app 上选择**
   - 过滤：选本对象一个字段（默认与目标对象同名字段，如 项目类型）
   - 返回：勾选目标对象字段（默认主键 + 名称，**主键强制包含**）
5. **唯一字段默认主键**（已有默认，需保证不被改坏）
