# 表单：级联下拉 与 条件隐藏

> 学习样本：`PP6/表单/项目表单包含级联关系，以及隐藏字段的办法.zip`
> （内为 `form/001-project_create_.xml`，598KB，56 个控件，`key=project_create_`，
> 「三九项目立项信息表单」）。另对照了 `PP6/表单/` 下另外 4 个真实表单包。
> 整理日期：2026-10-29。

这两样能力在系统里**都不是靠脚本，也不靠控件自身逻辑**，而是两组纯配置：

| 能力 | 配置位置 | 关键字段 |
|---|---|---|
| 级联下拉 | 子控件的 `fieldOptions` | `cascadeEnabled` / `cascadeParentCode` |
| 条件隐藏 | `formDef` 的 `extendAttr.formRules` | `action:"hidden"` + `condition` |

---

## 一、级联下拉

### 1. 真实结构

子控件的 `fieldOptions` 只多两个键：

```json
{
  "datasource": "dictionary",
  "dictionary": "project_create_productClassification",
  "options_source": "bo_attr",
  "cascadeEnabled": true,
  "cascadeParentCode": "productCategory",
  "init_linkage": true
}
```

样本里 4 个「品种类别 / 品种分类 / 战略类别 / 项目类别代码」，真实配置是：

| 控件 | cascadeEnabled | cascadeParentCode |
|---|---|---|
| `productCategory` 品种类别 | false | （无） |
| `productClassification` 品种分类 | **true** | `productCategory` |
| `strategyCategory` 战略类别 | **true** | `productCategory` |
| `projectCategoryCode` 项目类别代码 | false | `""` |

**要点**：根节点保持 `false` + 不写 `cascadeParentCode`；只有子节点打开开关，
值是**同表单里父控件的 name**。没有「层级号」「路径」之类的额外描述——
父子关系完全由字典项自身携带。

### 2. 生效前提（最容易踩的坑）

`cascadeParentCode` 只是「听谁的」，**「听谁之后还剩哪些选项」是靠字典的父子关系决定的**。
所以：

- 子控件的选项必须来自**层级字典**（字典项本身有 parent 关系）；
- 用值来源（数据集）拉出来的下拉、或固定候选值下拉，配了也不生效；
- 我们生成器里 `dic` 字段的字典是「自定义选项」（`optionSource=BO_ATTR_DIC_TYPE`），
  导入后要在字典管理里把子选项挂到父选项下，级联才真的过滤。

### 3. 控件形态：必须是「下拉 + 选项来源=数据字典」

拿 `品种类别 / 品种分类` 这两个字段逐键对过，样本里它们**都不是「数据字典」树控件**，
而是普通下拉：

| | 样本 `productCategory` | 样本 `productClassification` |
|---|---|---|
| `fieldType` | `select` | `select` |
| `datasource` | `dictionary` | `dictionary` |
| `options_source` | `bo_attr` | `bo_attr` |
| `dictionary` | `project_create_productCategory` | `project_create_productClassification` |
| `init_linkage` / `selection` | `true` / `true` | `true` / `true` |
| `filterable` | `true` | `true` |
| `cascadeEnabled` | `false` | **`true`** |
| `cascadeParentCode` | （无） | **`productCategory`** |

「数据字典」控件（`fieldType=dictionary`）是**树形选择**，骨架里带
`select_mode=leaf` / `display_mode=path` / `split="/"`，按字典层级展开、只选叶子，
根本没有「听哪个控件」的概念。所以级联配在它身上不会有效果。

生成器现在的处理：**级联链上的控件（子级 + 被引用为父级的）自动出成
`select + datasource=dictionary`**，父级补 `cascadeEnabled=false`，容器外的普通
字典字段仍走原来的树控件。转换时会打一条 notice 说明。

### 4. 父子关系存在哪：`iform_cat_dic.depend_values_`（导出包不带）

只读连库（`~/.pp6kit/nlq.json` 的 db 配置）查到的表结构：

| 字段 | 说明 |
|---|---|
| `parent_id_` | **指向字典类型**（`iform_cat_type.id_`），不是父选项，别误用 |
| `depend_values_` | `varchar(1000)`，默认 `[]`，**父子依赖只能存这里** |

而业务对象导出包的 `<tns:dictionary>` 只有
`typeKey / key / name / sn / disabled` + `attrs_`（样式 JSON），
**不带 `depend_values_`**——5 个真实导出包全部搜不到 depend 字样。
这也解释了官方那个「级联样本」为什么只导出了 `form` 模块：字典侧的分组关系压根不在包里。

结论：导入包能配到「听谁的」，配不到「哪些子项属于哪个父项」。
后者必须在系统「字典管理」里挂，或直接补库里 `depend_values_`。
`validate` 会对每个级联字段给一条 info 提醒这件事。

### 4. 业务对象属性上还有一份（2026-10-31 补充）

出处：`PP6/业务对象/项目立项业务对象.zip`（`bo/001-project_create.xml`，82 字段 / 357 条字典项）。
这份包说明级联**不只配在表单控件上，业务对象字段自己也能配**，位置是 `attribute` 的 `options`：

```json
{"isMultiple":false,...,"format":null,"cascadeEnabled":true,"cascadeParentCode":"productClassification"}
```

包里 5 个字段连成一条链，其中 `classificationId` 是**关联对象**、不是选项：

| sn | 字段 | 类型 | cascadeEnabled | cascadeParentCode |
|---|---|---|---|---|
| 27 | classificationId 隶属的项目类型 | **object** | — | — |
| 45 | productCategory 品种类别 | dic | true | classificationId |
| 46 | productClassification 品种分类 | dic | true | productCategory |
| 47 | strategyCategory 战略类别 | dic | **false** | productCategory |
| 48 | projectRegistrationCategory 项目注册类别 | dic | true | strategyCategory |
| 49 | projectCategoryCode 项目类别代码 | dic | **false** | `""` |

三个要点：

1. **父级可以是关联对象**（`dataTypeNew=object`）。「只有选项控件能当父级」是错的。
2. **`cascadeEnabled` 和 `cascadeParentCode` 是两个独立键**。`strategyCategory` 是
   `false + "productCategory"`——记着父级但没启用。我们约定「填了父级就启用」，
   清空这一格等于关掉。
3. 这份包的字典项 key 是**语义化短码**（`ZY` 中药 / `HY` 化药 / `OTC` / `SK` 双跨），
   不是我们生成的 md5 短码（`78ac30b4`）。而且「品种分类」只有 6 项
   （OTC / RX / 双跨 / 其他 / 大健康 / N/A），**不是**需求稿里按类别分组的 17 项。
   线上落地的形态就是「扁平字典 + 级联声明」，分组关系仍在系统侧。

### 5. 我们的实现：两层 + 自动继承

| 层 | Excel 位置 | 写进哪里 |
|---|---|---|
| 业务对象字段 | `2_字段` →「级联父字段」 | attribute 的 `options.cascadeEnabled` / `cascadeParentCode` |
| 表单控件 | `4_表单控件` →「级联父字段」 | 控件 `fieldOptions` 里的同名两个键 |

**只填 `2_字段` 就够**：出表单时控件这层若没填，会自动继承业务对象字段的配置并打一条
notice。`4_表单控件` 那格留给两个场景——覆盖字段层的设置，或者字段层没配但表单里要级联。

反解时把 `cascadeEnabled/cascadeParentCode` 提到「级联父字段」这一个来源，并从 `options`
里删掉：否则用户在 Excel 里清空这一格，`options` 里的旧值还会被原样带出去，级联关不掉。
`cascadeEnabled=false` 的字段按「不级联」反解（语义等价）。

## 二、条件隐藏

### 1. 真实结构

藏在 `formDef@extendAttr` 的 `formRules` 数组里。一条规则 = 一个条件 + 一个动作：

```json
{
  "id": "1srq57k",
  "controlName": "mahHolder",          // 要隐藏的控件
  "controlLabel": "MAH持有人",
  "controlType": "select",
  "action": "hidden",
  "condition": {
    "type": "group",
    "rules": [{
      "field": {                        // 条件字段的「快照」，用于界面显示人话
        "name": "strategyCategory", "label": "战略类别",
        "field_type": "dictionary", "field_data_type": "dic",
        "field_options": { "dictionary": "project_create_strategyCategory", ... },
        "icon": "iform-icon-radio",
        "form_rule_source": "object", "form_display_label": "战略类别"
      },
      "value": "QT", "operator": "equal",
      "rule_condition": "and",
      "rule_id": "1v1s81h",
      "operator_label": "等于", "value_label": "其他"
    }]
  },
  "value": "true",
  "clearOnHide": "global"
}
```

同层还有两个开关：

- `extendAttr.formRuleClearOnHide: true` —— 隐藏时清空已填值（切条件后不残留）；
- `extendAttr.setHiddenField: "count"` —— 5 个样本**全部**是这个值，照抄即可。

### 2. 语义（样本实测推断）

- **动作只有 `hidden`**，没有 `show`。想表达「等于 X 时才显示」，要反过来写
  「**不等于** X 时隐藏」——样本里 `gradeId`（项目分级）就是这么配的：
  `strategyCategory != "XP"(新品) → 隐藏`。
- **同一控件的多条规则是并列的独立记录，不是一条里塞多个条件 ⇒ 满足任一即隐藏（OR）**。
  样本里 `mahHolder` 有 2 条（`为空` 和 `等于 QT`），`specification2_` 也有 2 条。
- 一条规则内部 `condition.rules[]` 的多条件用 `rule_condition: and/or` 连接，
  但样本里每条都只有 1 个条件，**多条件的 AND 组合没有真实样本验证**。
- `clearOnHide` 样本只有 `global` 一个值；我们生成时关掉写成 `none`（未验证）。

### 3. 算子

样本里只出现过 3 个：`equal` / `not_equal` / `is_empty`。
我们另加了 `is_not_empty`（同为「空判断」族，推测存在，未在样本中验证）。
其余算子（包含、大于、区间…）一律没有放出——生成器只写这四个，
`validate` 会把不认识的算子当错误拦下。

### 4. 条件值是「选项值」不是「选项名」

样本里 `value: "QT"`、`"XP"`、`"YZXPJ"` 是短码，`value_label` 才是「其他 / 新品 / 一致性评价」。
我们自己生成的字典，选项值是 md5 生成的 8 位短码（`630ddeea`），用户填不出来，
所以生成器加了换算：**Excel 里条件值可以直接写中文选项名**，出包时换成对应短码；
换算不出来（引用线上已有共享字典、值本来就是 `QT` 这种）就原样保留并提示。

## 三、这个样本值得学的表单设计方式

| 观察 | 说明 | 我们是否照搬 |
|---|---|---|
| `fieldset` 分组卡片 | 5 个分组：基础信息 / 关键信息 / 里程碑计划 / 预算计划 / 附件上传，每个 fieldset 里再套 `grid_layout` | 暂不：我们用「行 grid（每行最多 2 列）」铺平，结构更简单、校验也好写；分组靠 `desc` 体现。若要卡片式分组，需在 `gen_form` 里加一层 fieldset 容器 |
| 一行两列 | 每个 `grid_layout` 的 columns，配 `labelWidth 106` | 已一致（`_max_per_row` 恒为 2） |
| `customClass: pp-drawer-add`、`width: 90`、`openType: drawer` | 抽屉打开、90% 宽 | 已按表单类型在 `model.form_style()` 里区分（新建 45% / 详情 90%） |
| 按钮只用 取消 / 保存并继续 / 保存，仅「保存」是主色 | 手册一致 | 已实现（`render` 里筛 `ext["buttons"]`） |
| 大量 `formRights`（529 条，`rightsType: node`，按流程节点授权） | 流程表单按节点配字段权限，`read: allUsers` + `edit: BpmRole(NodeTodoHandler,BpmCreator)` | 我们目前是固定模板（`rightsType: form`）。流程节点权限需要流程定义，生成器不做流程，这块保持现状 |
| `tableField` 子表格（里程碑计划表、预算编辑表格） | 明细行录入用 `tableField`，配 `configurableColumns` | **已支持（2026-11-15）**：字段类型选「表格」+「2.1_表格列」定义列，表单自动出 `tableField` 并直挂分区容器；列定义见 README「表格字段」一节 |

结论：**这个样本的价值在「级联 + 条件隐藏」两个配置块，不在布局**。布局上我们现有的
「两列 + 行 grid」更稳，不需要为了像它而改成 fieldset 嵌套。

## 四、我们（pp6kit）怎么用

### 1. Excel 里怎么写

**级联**——`4_表单控件` 新增列「级联父字段」：

| 表单key | 字段编码 | 显示标签 | 控件类型 | 取值来源 | 级联父字段 |
|---|---|---|---|---|---|
| create_demo | category | 品种类别 | dictionary | demo_category | |
| create_demo | itemType | 品种分类 | dictionary | demo_itemType | category |

**条件隐藏**——新工作表 `8_隐藏规则`，一行一条：

| 表单key | 隐藏控件 | 依赖控件 | 判断条件 | 条件值 | 条件值说明 | 隐藏时清空 |
|---|---|---|---|---|---|---|
| create_demo | budget | needBudget | 不等于 | 是 | 是 | 是 |
| create_demo | budget | needBudget | 为空 | | | 是 |

判断条件只有 等于 / 不等于 / 为空 / 不为空；「为空」类不用填条件值。
需要 OR 就写多行（同一隐藏控件重复出现）。

### 2. 代码位置

| 环节 | 文件 | 说明 |
|---|---|---|
| 模型 | `pp6kit/model.py` | `FormField.cascade_parent`、`HideRule`、`Form.hide_rules`、`OP_BY_LABEL/HIDE_OPERATORS` |
| 生成 | `pp6kit/gen_form.py` | `_apply_options` 写 `cascadeEnabled/cascadeParentCode`；`build_rules()` 写 `formRules`；`_resolve_rule_value()` 做选项名→选项值换算 |
| 选项值表 | `pp6kit/gen_bo.py` | `dict_choice_codes(bo, field_code)`，与字典生成同算法 |
| Excel 规格 | `pp6kit/spec.py` | 新列「级联父字段」、新表 `8_隐藏规则` |
| 读写 | `pp6kit/template.py` / `pp6kit/reader.py` | 模板回写 / 读入 |
| 校验 | `pp6kit/validate.py` | `_validate_cascade`（父级存在、类型、成环）、`_validate_hide_rules`（控件存在、算子、条件值可解析、重复规则） |
| 反解 | `pp6kit/inspect.py` | 导出的包反解回级联 + `formRules`（样例包实测 2 条级联 + 16 条隐藏全部还原） |
| AI | `pp6kit/ai_form.py` / `pp6kit/ai_refine.py` | 布局 JSON 支持 `cascades` / `hideRules`；微调时原样继承，不丢配置 |

### 3. 校验会拦什么

- 级联父级不在本表单 / 指向自己 / 成环 → **error**
- 级联父级不是选项类控件、子控件不是选项类 → warn
- 子控件选项来自值来源而非层级字典 → warn（级联可能不生效）
- 隐藏规则引用的控件不存在、算子不认识、「等于/不等于」没填条件值 → **error**
- 条件值既不是选项名也不是选项值 → warn（条件永远不成立，且界面上看不出来）

## 五、AI 侧契约（确保模型产出的需求能被识别）

模型只输出「布局 JSON」，**不写 XML**。级联和隐藏都用固定键名表达，键名大小写敏感：

```json
{
  "groups": [{"title": "基本信息", "fields": ["name", "productCategory", "productType"]}],
  "required": ["name"],
  "fullRow": [],
  "cascades": {"productType": "productCategory"},
  "hideRules": [
    {"target": "budget", "source": "needBudget", "operator": "不等于", "value": "是"}
  ]
}
```

- `cascades`：`{"子字段编码": "父字段编码"}`，也兼容 `[[子, 父]]` 和
  `[{"child": .., "parent": ..}]` 两种写法。
- `hideRules[]`：`target` 要隐藏的字段、`source` 条件字段、`operator`
  取 等于/不等于/为空/不为空（写英文 `equal`/`not_equal`/`is_empty`/`is_not_empty` 也认）、
  `value` 填**选项名原文**（中文），为空类不填。
- 为了让模型判断得出「谁能级联谁」，发给它的字段清单里选项类字段会带上
  `选项: [...]`（前 10 个）。

### 落到我们这边时的三种形状都接

| 形状 | 出处 | 谁读 |
|---|---|---|
| `fields[].cascadeParent` | `ai_form.to_dict` 逐行输出 | `webui.ai_apply_bo`、前端逐格展示、`ai_refine._carry_over_logic` |
| `form.cascades` = `{子:父}` | `to_dict` 同时给一份 | `ai_apply_bo`（兼容外部脚本/旧调用） |
| `form.hideRules[]` | `to_dict` | `ai_apply_bo`、`ai_refine` |

### 识别不了时的降级（绝不静默丢）

- 引用了不存在的控件 → 跳过这条，写进 `notices`：`隐藏规则引用了不存在的控件 xxx，已跳过`
- 算子不认识 → 按「等于」处理并提示
- 「等于/不等于」没给值 → 跳过并提示
- 条件值既不是选项名也不是选项值 → **保留原值**并提示（可能引用的是线上已有字典）
- 级联父级不在同表单 → 跳过该级联

### 肉眼可核对

AI 预览里会直接显示：级联字段下方标「级联 品种类别」，表单底部列出
「条件隐藏 2 条 · 条件成立即隐藏」以及每条规则（`战略类别 等于 其他 → 隐藏 MAH持有人`）。
用户不用等导入系统才知道 AI 有没有听懂。

### 链路自测方法

```
模拟 AI 布局 JSON → ai_form.build_form → ai_form.to_dict
  → webui.ai_apply_bo（= 点「导出 Excel」）→ reader.read_workbook
  → builder.build → 解压 form/*.xml
```
实测结果：级联 1 条、隐藏 2 条，Excel 的「级联父字段」列与 `8_隐藏规则` 表都正确落位，
出包 XML 里 `cascadeEnabled/cascadeParentCode` 与 `formRules` 与官方样本结构一致，
条件值「是/其他」被换算成字典短码（`1296aa24` / `15dd2bac`）。

## 六、尚未验证 / 已知限制

1. **多条件 AND**：只见过单条件规则，`rule_condition: and` 的组合未验证。
2. **`clearOnHide: none`**：样本只有 `global`，关掉清空时的取值未验证。
3. **`is_not_empty`**：由 `is_empty` 类推，未见真实样本。
4. **表单项快照里的 icon**：`iform-icon-radio/font/number/calendar/link/user` 是推断值，
   图标不对只影响设计器里的显示，不影响隐藏逻辑。
5. **级联的实际过滤**依赖字典的层级结构，生成器只写开关，字典得在系统里挂好父子关系。

## 附录：品种类别 / 品种分类（需求稿 vs 导出包）

需求稿：`PP6/项目基本信息表单-尹姣定.xlsx`（169 行，就是导出样本那张「三九项目立项信息表单」）

| 字段 | 需求稿写法 | 导出包实际配置 |
|---|---|---|
| 品种类别 | 【下拉选择】候选值：中药、化药、大健康、生物制品、N/A | `select` + 字典 `project_create_productCategory`，`cascadeEnabled=false` |
