## 七、对生成器的直接影响

1. **不要强制模块归属**。125/195 个对象既无 `moduleId` 也无 `moduleName`（已用详情接口交叉核实），生成器如果要求必填模块，绝大多数存量对象都过不了。
2. **列表确实是「多维表格」**：`showType=dimension` 占 175/207（85%），与手册「列表统一用 showType=dimension」**一致**。`composeType=treeList`（182/207）是**组合方式**（树形列表），不是 showType，两者不冲突——第一次读这两个字段时把它们混了，特此更正。
3. **列表列配置不在列表接口里**（207 个只有 1 个带 fieldList），要拿列配置得走单独的列接口或 template 详情。
4. **「选择器」页签不空（203 条），但表单选择器控件仍未启用**（`iform_form_selector` 0 行），两件事分开看，见第五节。
5. **数据集以物理表为主**（table 118/178，66%），与手册「建议选物理表」一致；`thirdparty` 23 个是外部数据源，生成器不该碰。
6. **对象规模差异大**：最大 56 字段（`pp_task`），平均 22 字段。生成器的字段表 UI 要能容纳 50+ 字段。
7. **`bo/def/query` 不返回 `attrList`**（195 条全为空），字段必须逐对象调 `bo/def/manage?boDefId=` 才有；`form/def/query` 同理不返回 `formHtml` 和 `formFieldList`。批量取结构时别指望列表接口。
